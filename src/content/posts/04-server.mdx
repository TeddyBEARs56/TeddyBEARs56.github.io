## 이번에 할 일

1. **서버에서 명령 한 줄로 MLX 서버를 띄운다.** 사무실 망의 다른 기계가 질문을 보낼 수 있게 한다.
2. **노트북에서 질문을 보낸다.** 다른 기계에서 정말 답이 오는지, 답이 어떤 모양인지 본다.
3. **이어서 물어, 서버가 앞의 대화를 아는지 본다.** 챗봇처럼 쓰려면 대화가 이어져야 한다.
4. **내 컴퓨터에서 OpenAI 공식 라이브러리로 묻는다.** ChatGPT용 프로그램을 주소만 바꿔 붙일 수 있는지 본다.
5. **여럿이 동시에 묻게 한다.** 여러 사람이 쓰는 7단계를 미리 맛본다.

## 명령 한 줄로 서버 띄우기

실습 화면은 셋으로 나눴습니다. 왼쪽은 Claude와 대화하는 창입니다. 오른쪽 위는 서버, 오른쪽 아래는 노트북 창이고, 둘 다 SSH로 원격 접속했습니다. 서버 창에서 한 줄을 쳤습니다.

<Code title="터미널, 서버" wrap>

```sh
$ mlx_lm.server --model ~/models/mlx/Qwen3.8-27B-4bit --host 0.0.0.0 --chat-template-args '{"enable_thinking":false}'
UserWarning: mlx_lm.server is not recommended for production as it only implements basic security checks.
INFO - Starting httpd at 0.0.0.0 on port 8080...
```

</Code>

| 부분 | 뜻 |
| --- | --- |
| `--model` | 띄울 모델. 3단계에서 받은 MLX용 Qwen |
| `--host 0.0.0.0` | 사무실 망의 어느 기계가 보내도 받는다. 빼면 서버 자신이 보낸 질문만 받는다 |
| `--chat-template-args` | 생각 모드를 끈다. 초당 7토큰짜리 모델이 답하기 전에 생각까지 하면, 답 하나에 1~2분씩 걸린다 |
| 문 번호(포트) | 적지 않아서 기본값 `8080` |

모델을 메모리에 올리는 데는 10초쯤 걸렸습니다. 처음에는 같은 명령을 노트북 창에 쳤다가 「그런 명령은 없다」는 답을 받았습니다. MLX는 애플 칩 전용이라 서버에만 있습니다.

<Note title="열쇠가 없는 서버">
경고문이 말하듯 이 서버는 기본적인 보안 검사만 합니다. 허락받은 사람만 쓰게 하는 암호인 API 열쇠도 없습니다. 그래서 켜 둔 동안에는 같은 사무실 망의 누구나 쓸 수 있습니다. 시험하는 동안만 열고, 끝나면 끄기로 했습니다. 열쇠는 7단계에서 붙입니다.
</Note>

## 다른 기계에서 질문하기

노트북 창에서 서버 주소로 두 가지를 보냈습니다. 하나는 「무슨 모델이 있느냐」는 물음이고, 하나는 실제 질문입니다. 윈도우 명령창은 한글을 그대로 넘기면 깨지기 쉽습니다. 그래서 손으로 직접 보내는 이 첫 시험은 영어로 했습니다.

<Code title="명령 프롬프트, 노트북" wrap>

```sh
> curl http://192.168.x.x:8080/v1/models
{"object": "list", "data": [{"id": ".../Qwen3.8-27B-4bit", "object": "model", ...}]}
> curl http://192.168.x.x:8080/v1/chat/completions -H "Content-Type: application/json" -d "{\"messages\":[{\"role\":\"user\",\"content\":\"What is 1+1? Answer in one short sentence.\"}],\"max_tokens\":40}"
{"id": "chatcmpl-...", "object": "chat.completion", "choices": [{"index": 0, "finish_reason": "stop", "message": {"role": "assistant", "content": "1+1 equals 2."}}], "usage": {"prompt_tokens": 25, "completion_tokens": 8, "total_tokens": 33}}
```

</Code>

주소는 `/v1/models`와 `/v1/chat/completions`이고, 질문은 `messages`에 싸서 보냅니다. 이 모양이 OpenAI API와 똑같습니다. API는 프로그램이 다른 프로그램에 일을 맡기는 정해진 창구입니다. 이 점이 4단계의 핵심입니다. 답장은 이렇게 읽습니다.

| 부분 | 값 | 뜻 |
| --- | --- | --- |
| `content` | `1+1 equals 2.` | 모델의 답 |
| `finish_reason` | `stop` | 스스로 답을 끝냈다. 한도에 걸려 잘리면 `length` |
| `usage` | 질문 25 + 답 8 = 33토큰 | 이번에 쓴 양을 글 조각인 토큰으로 셌다. 유료 API라면 이 숫자로 요금을 매긴다 |

서버 창에는 질문이 올 때마다 기록이 한 줄씩 찍혔습니다. 어느 기계에서 왔는지, 질문을 몇 토큰까지 읽었는지가 보입니다.

<Code title="터미널, 서버">

```sh
192.168.x.x - - [13/Nov/2026 16:56:16] "POST /v1/chat/completions HTTP/1.1" 200 -
INFO - Prompt processing progress: 25/25
```

</Code>

한국어 대화는 명령창 대신, Claude가 노트북에 만들어 준 작은 도우미로 했습니다. PowerShell로 짠 파일입니다. 질문을 받아 서버에 보내고, 답과 속도를 보여 줍니다.

| 질문 | 답 | 속도 |
| --- | --- | --- |
| 로컬 LLM이 뭔지 초등학생에게 설명하듯 세 문장으로 알려 줘 | 인터넷 연결 없이 내 컴퓨터나 스마트폰 안에서 직접 작동하는 똑똑한 인공지능 친구야. (…) 내가 쓴 내용이 밖으로 새어 나가지 않아서 더 안전해. | 81토큰, 13.5초, 초당 `6.0` |

3단계에서 잰 초당 6.9토큰보다 조금 느립니다. 질문을 읽는 시간과 망을 오가는 시간까지 들어간 체감 속도라서 그렇습니다.

## 서버는 대화를 기억하지 않는다

한 번 묻고 답하는 건 됐습니다. 이번에는 앞에서 한 말을 아는지 보려고, 같은 도우미로 바로 이어서 물었습니다.

| 질문 | 답 |
| --- | --- |
| 내가 방금 뭘 물어봤지? | 아니요, 이번 대화에서 아직 질문을 하신 적이 없습니다. |

서버는 질문 하나를 받으면 답 하나를 주고 끝납니다. 앞의 대화는 남기지 않습니다. 그럼 챗봇은 어떻게 대화를 이어 갈까요? **보내는 쪽이 지난 대화를 매번 통째로 다시 보냅니다.** 그렇게 하는 도우미로 다시 해 봤습니다.

<Code title="대화 도우미의 핵심, 노트북">

```powershell
$messages += @{ role = 'user'; content = $q }
$r = Invoke-RestMethod -Uri 'http://192.168.x.x:8080/v1/chat/completions' -Method Post -Body ...
$messages += @{ role = 'assistant'; content = $r.choices[0].message.content }
```

</Code>

| 차례 | 내가 친 것 | 보낸 양 | 답 | 걸린 시간 |
| --- | --- | --- | --- | --- |
| 1 | 내 이름은 ○○야. 기억해 줘 | 23토큰 | 이름을 잘 기억해 두겠습니다 | 8.9초 |
| 2 | 내 이름이 뭐라고 했지? | **94토큰** | ○○님이라고 하셨죠! | **2.6초** |

- 보낸 양이 23토큰에서 94토큰으로 늘었다. 앞의 질문과 답까지 같이 보냈기 때문이다. 기억은 서버가 아니라 보내는 쪽이 한다. 2단계에서 정한 「기억할 글 길이」가 이 숫자의 한계다.
- 더 많이 보냈는데 더 빨랐다. 서버에는 방금 읽은 앞부분을 잠시 붙잡아 두는 **임시 저장(prompt cache)** 기능이 있다. 그래서 새로 붙은 부분만 읽었다. 서버 기록에는 `Prompt Cache: 3 sequences, 0.46 GB`처럼 찍혔다. 대화를 기억하는 게 아니라, 속도를 위해 잠시 두는 저장이다.

## OpenAI 라이브러리를 그대로

앞에서 서버가 OpenAI API와 같은 모양으로 주고받는 걸 봤습니다. 실제 프로그램들은 보통 OpenAI 공식 라이브러리로 질문합니다. 라이브러리는 프로그램에 가져다 쓰는 코드 묶음입니다. 그래서 이번에는 내 컴퓨터에서 그 라이브러리로 물었습니다. 바꾼 건 서버 주소 하나뿐입니다. 파일은 Claude가 만들었고, 실행은 대화창에서 제가 했습니다.

<Code title="openai_hello.py의 핵심, 내 컴퓨터">

```python
from openai import OpenAI

client = OpenAI(base_url="http://192.168.x.x:8080/v1", api_key="none")
r = client.chat.completions.create(model=model, messages=[{"role": "user", "content": "..."}])
```

</Code>

<Code title="터미널, 내 컴퓨터">

```sh
$ uv run ~/llm-lab/openai_hello.py
서버의 모델: Qwen3.8-27B-4bit
[한 번에 받기] 안녕하세요, 오늘도 좋은 하루 보내세요! (답 12토큰)
[흘려 받기] 따스한 햇살 아래 만물이 깨어나 꽃이 피어나는 봄,
뜨거운 태양 아래 생명력이 가장 왕성하게 불타오르는 여름,
풍성한 수확과 단풍으로 물든 대지가 아름다운 가을,
하얀 눈이 덮인 고요함 속에서 자연이 잠시 숨을 고르는 겨울.
--- 첫 글자까지 1.0초, 조각 70개, 전체 11.4초
```

</Code>

- **주소 한 줄만 바꿨는데 그대로 됐다.** 열쇠 칸인 `api_key`에는 아무 글자나 넣었다. ChatGPT용으로 만든 프로그램 대부분을 이 서버에 붙일 수 있다는 뜻이다. 6단계에서 이 방법을 쓴다.
- **흘려 받으면 첫 글자가 1초 만에 나온다.** 흘려 받기는 답이 다 만들어지길 기다리지 않고, 글자가 만들어지는 대로 조금씩 받는 방식이다. 이번에는 조각 70개로 나눠 받았다. 네 줄을 다 쓰는 데는 11.4초가 걸렸다. 사람이 느끼는 빠르기는 전체 시간보다 첫 글자까지의 시간이다.

## 여럿이 동시에 물으면

7단계를 미리 맛보려고, 1명, 2명, 4명이 같은 순간에 같은 질문을 보내게 했습니다. 답 길이는 최대 80토큰입니다.

| 동시에 묻는 사람 | 한 사람이 기다린 시간 | 서버 전체 속도 |
| --- | --- | --- |
| 1명 | 7.0초 | 초당 `5.7`토큰 |
| 2명 | 6.4초 | 초당 `12.6`토큰 |
| 4명 | 7.9초 | 초당 `20.2`토큰 |

- **4명이 한꺼번에 물어도 각자 기다린 시간은 거의 늘지 않았다.** 서버가 네 질문을 묶어서 함께 답을 썼다. 한 토큰을 쓸 때마다 모델 16GB를 한 번 읽어야 한다. 서버는 한 번 읽은 김에 네 사람 몫을 같이 계산한다. 속도를 막는 건 읽기라서, 사람이 늘어도 읽는 횟수는 그대로다.
- 이번에는 모두 같은 질문이라 임시 저장 덕도 봤다. 서버 기록을 보면 1명일 때는 질문을 `27/27`토큰 읽었다. 2명과 4명일 때는 `1/1`토큰만 읽었다. 서로 다른 긴 질문이 몰리면 이보다 느릴 것이다. 7단계에서 제대로 잰다.

열쇠가 없으니, 시험을 마치고 서버 창에서 `Ctrl + C`로 서버를 껐습니다. 사무실 망에 열어 둔 문도 함께 닫혔습니다.

## 배운 것

- 서버는 명령 한 줄이면 뜬다. 열쇠가 없으니 시험하는 동안만 연다.
- OpenAI와 같은 형식이라, ChatGPT용 프로그램을 주소만 바꿔 붙일 수 있다.
- 서버는 대화를 기억하지 않는다. 보내는 쪽이 지난 대화를 매번 다시 보낸다.
- 흘려 받으면 첫 글자가 1초 만에 나온다. 사람이 느끼는 빠르기는 이것이다.
- 여럿이 동시에 물어도 한 사람이 기다리는 시간은 거의 같다. 모델을 한 번 읽어 여러 답을 함께 쓴다.

## 다음 단계로

이제 다른 기계에서도 모델을 쓸 수 있습니다. 하지만 서버는 제가 터미널 창에 친 명령 하나로 돌았고, 창을 닫으면 함께 사라집니다. 그래서 5단계에서는 사람이 창을 열어 두지 않아도 서버가 늘 켜져 있게 합니다.
