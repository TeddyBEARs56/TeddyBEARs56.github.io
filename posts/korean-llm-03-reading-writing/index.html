국산 LLM에게 요약과 커밋 메시지를 맡겨 보니

2편에서 우리 기계에 올린 국산 모델에게 이번에는 한국어로 하는 일을 맡겼습니다. 글을 요약하는 일과, 이 블로그의 변경 내용을 보고 커밋 메시지를 쓰는 일입니다.

올린 날
2026-11-20
읽는 시간
약 7분

이번에 할 일

  1. 한국어 글 세 편을 세 문장으로 요약하게 한다. 2편과 같은 지시문을 쓴다.
  2. 이 블로그의 커밋 일곱 개에 메시지를 쓰게 한다. 지시문은 지난 연재 8단계에서 고친 것을 그대로 쓴다.
  3. 모델 이름을 가리고 채점한다. 채점 기준은 답을 보기 전에 정한다.

시험 방법

노트북(Arc 140V 내장 GPU, 메모리 32GB)의 Ollama 0.40.16에서 돌렸습니다. 요청은 Mac mini의 시험 스크립트가 같은 네트워크로 보냈습니다. 2편에서 노트북에 올린 국산 모델 넷과, 견줄 해외 모델 둘입니다. SEED Think는 2편에서 올라가지 않아 뺐습니다. 크기는 기억할 글 길이 16,384토큰으로 올렸을 때 Ollama가 보고한 값이라, 8,192토큰으로 잰 2편의 표와 다릅니다.

모델 만든 곳 올렸을 때 크기
Mi:dm 2.0 Base KT 10.2GB
Kanana-2 30B 카카오 19.5GB
EXAONE 4.5 LG 20.9GB
Tri-21B-Think 트릴리온랩스 16.0GB
Qwen3.6 35B 알리바바 17.7GB
Gemma 4 26B 구글 14.2GB

Gemma 4는 노트북이 웹 UI용으로 띄우는 모델과 같은 GGUF 파일을 Ollama에 들여온 것입니다. 모든 요청은 온도 0, 기억할 글 길이 16,384토큰으로 한 번씩 보냈고, 생각은 끌 수 있는 모델이면 껐습니다.

  • 요약: 「다음 글을 한국어 세 문장으로 요약해 주세요.」 뒤에 이 블로그의 글을 붙였다. 국산 LLM 1편의 앞부분(2편과 같은 글), 「MLX, GGUF, Ollama는 무엇이 다른가」의 한 부분, Cybug 하나로, 1,860~2,347자다. 답은 400토큰까지다.
  • 커밋 메시지: 8단계 도구처럼 최근 커밋 제목(10개까지), 바뀐 파일 목록, diff를 보냈다. 커밋은 이 블로그의 것 일곱 개로, diff가 2,074~9,726자다. 답은 600토큰까지다.
  • Tri-21B-Think: 2편에서 본 대로 생각을 끌 수 없다. 그래서 답 한도를 4,096토큰으로 늘리고, 마지막 </think> 뒤만 답으로 쳤다.

커밋 메시지의 지시문은 이렇습니다.

채점은 이렇게 했습니다.

  1. 기준을 먼저 정했다. 답이 나오기 전에 요약 글마다 담아야 할 핵심 셋과, 커밋 메시지를 볼 네 가지(무엇을 바꿨나, 형식, 왜 바꿨나, 지어낸 것)를 적어 두었다.
  2. 이름을 가렸다. 문항마다 답 여섯 개의 순서를 섞고 A~F를 붙여 한 파일로 묶었다. 1,500자가 넘는 답은 앞부분만 실었다. EXAONE 4.5의 커밋 답 일곱 개가 모두 여기에 들었다.
  3. 새 대화의 Claude가 채점했다. 이 시험을 짠 대화를 모르는 Claude가 묶음 파일만 보고 60개를 매겼다. 채점이 끝난 뒤 이름을 붙였다. 채점자가 채점하면서 더한 기준은 아래 표 밑에 적었다.

모델마다 대화 형식(채팅 템플릿)이 달라서, 지시문이 모델에 실제로 들어갔는지도 확인했습니다. Ollama 기록을 보면 Mi:dm, EXAONE 4.5, Tri-21B-Think는 GGUF 안의 대화 형식을, Kanana-2는 Hugging Face가 준 대화 형식을 썼습니다. 네 형식 모두 지시문을 system 자리에 넣습니다. Mi:dm은 자체 기본 안내 뒤에 이어 붙입니다.

커밋 메시지

모델 내용이 맞음 형식이 맞음 둘 다 맞음 지어낸 것
Gemma 4 26B 7 7 7 0
Qwen3.6 35B 4, 일부 2 3 2 7
Kanana-2 30B 1, 일부 2 1 0 8
Mi:dm 2.0 Base 0 1 0 0
EXAONE 4.5 0 0 0 17
Tri-21B-Think 일부 1 0 0 8

칸의 뜻은 이렇습니다.

  • 내용이 맞음: diff의 주요 변경을 맞게 적은 수다. 「일부」는 일부만 맞거나 흐린 것이다.
  • 형식이 맞음: 최근 커밋처럼 한국어 한 줄 제목(70자 이내)이고, feat:이나 CI: 같은 영어 접두어가 없고, 제목 뒤에 빈 줄을 두고, 메시지 밖의 말이 없는 것이다.
  • 지어낸 것: diff에 없는 내용의 개수를 일곱 문항에서 더했다. 앞부분만 실은 답은 보이는 부분에서만 셌다.

채점자는 채점하면서 기준을 하나 더 세웠습니다. diff를 되풀이했거나, 메시지 대신 설명을 썼거나, 영어로 썼거나, 메시지 전에 끊긴 답은 커밋 메시지로 쓸 수 없다고 보고, 내용이 맞아도 「내용이 맞음」에서 뺐습니다. 미리 정한 기준에는 없던 것이라, 아래에서 내용만 따로 본 것을 함께 적었습니다.

Gemma 4는 일곱 개 모두 내용과 형식이 맞았습니다. 넷은 코드 주석에 적힌 이유까지 옮겼고, 지어낸 것이 없었습니다. 연재 목록을 접히게 바꾼 커밋에는 이렇게 썼습니다.

그때 Claude가 쓴 제목은 「타이틀은 흰 Cyborg 뒤에 회색 그림자로, 홈의 연재는 펼치고 접는 토글로」였습니다. Gemma 4는 코드의 이름(Wordmark, tail, details)을 그대로 썼고, Cyborg 글자를 모두 흰색으로 바꾼 것은 빠뜨렸습니다. 나머지 변경은 맞혔습니다.

Qwen3.6은 짧고 맞는 메시지가 많았습니다. 개인정보 안내 페이지를 더한 커밋에는 「개인정보 처리방침 페이지 추가 및 바닥글 링크 연결」 한 줄을 냈습니다. 다만 일곱 개 가운데 둘은 최근 커밋의 내용을 섞었고, 하나는 최근 커밋 네 줄을 그대로 옮겼습니다.

국산 모델 넷은 지시문을 받고도 대부분 메시지를 내지 못했습니다. 실패한 모양은 모델마다 달랐습니다.

  • Mi:dm 2.0 Base: 일곱 개 가운데 여섯 개에서 diff를 그대로 되풀이했다. 남은 하나는 최근 커밋 제목을 거의 그대로 옮긴 것이라, 형식은 맞았지만 내용이 틀렸다.
  • EXAONE 4.5: 일곱 개 모두 메시지 대신 설명 문서를 쓰다가 600토큰 한도에서 끊겼다. 첫 커밋에는 「다음은 제공된 커밋 정보와 CSS 변경 내용을 바탕으로 정리한 요약 및 설명입니다」로 시작해 소제목과 표를 늘어놓았다. 내용만 보면 풀이는 대체로 맞았지만, 접근성이나 가독성 같은 목적을 지어 붙였다.
  • Kanana-2 30B: 최근 커밋 제목을 그대로 옮기는 일이 잦았다. 첫 커밋에는 최근 커밋 열 줄을 다듬어 그대로 내놓았다. 지시문의 「’최근 커밋’의 언어와 형식을 그대로 따른다」를 내용까지 따르라는 뜻으로 읽은 것처럼 보였다.
  • Tri-21B-Think: 문항마다 생각부터 길게 썼고, 메시지 넷에 영어가 섞였다. 둘은 영어로만 썼다. 넷 가운데 둘은 내용만 보면 맞았다. 하나는 생각만 쓰다 4,096토큰 한도에서 끊겼다.

요약

모델 형식이 맞음 핵심을 담음 틀린 내용
Gemma 4 26B 0/3 6.5/9 0
Kanana-2 30B 0/3 6.5/9 3
EXAONE 4.5 3/3 6/9 4
Qwen3.6 35B 3/3 5.5/9 3
Tri-21B-Think 0/3 4.5/9 2
Mi:dm 2.0 Base 2/3 4/9 3

「형식이 맞음」은 한국어 세 문장에 요약만 낸 것입니다. 「핵심을 담음」은 글마다 정해 둔 핵심 셋을 다 담으면 1점, 일부만 담으면 0.5점으로 세 글에서 더했습니다. 「틀린 내용」은 글과 다르거나 글에 없는 내용의 수입니다.

요약은 커밋 메시지보다 차이가 작았습니다. 핵심 점수는 4~6.5점 사이였고, 위의 넷은 0.5~1점 차이였습니다.

  • Gemma 4와 Kanana-2가 내용을 조금 더 담았다. 하지만 둘 다 번호를 붙인 목록으로 써서 형식을 어겼다. Gemma 4는 「제시해주신 글의 요약본입니다.」 같은 앞말도 붙였다.
  • 세 문장을 지킨 것은 Qwen3.6과 EXAONE 4.5였다. Mi:dm은 셋 가운데 하나에 소개 문장이 붙어 네 문장이 됐다.
  • 틀린 내용이 없었던 것은 Gemma 4뿐이었다. 다른 모델은 라이선스를 모델 크기와 엮거나, 갈래를 셋에서 둘로 줄이거나, 글에 없는 결론을 덧붙였다.
  • 어느 모델도 다 담지 못한 대목이 있었다. 1편 글은 개발사 점수가 누가 쟀느냐에 따라 다르니 같은 표 안에서만 견주라고 적었는데, 이 단서를 분명히 쓴 답은 없었다.
  • Tri-21B-Think는 한 편을 요약하지 못했다. 생각만 쓰다 4,096토큰 한도에서 끊겼다.

답 쓰는 속도는 초당 토큰 수의 가운데 값입니다. EXAONE 4.5는 커밋 메시지마다 600토큰 한도까지 설명을 써서 오래 걸렸습니다. 이번에는 20.9GB 가운데 19.8GB만 GPU에 올라갔지만, 2편에서 노트북 GPU에 다 올렸을 때도 초당 3.8토큰이었습니다. Tri-21B-Think는 끝까지 간 여덟 문항에서 생각만 6만 5천 자 가까이 썼고, 나머지 두 문항은 4,096토큰을 생각에 다 쓰고 끊겼습니다.

알게 된 것

  • 커밋 메시지는 해외 모델이 앞섰다. Gemma 4는 일곱 개 모두 내용과 형식이 맞았고, Qwen3.6은 둘이었다. 국산 모델 넷은 둘 다 맞은 메시지가 하나도 없었다.
  • 국산 모델 넷은 지시문을 받고도 다른 것을 냈다. diff를 되풀이하거나, 메시지 대신 설명 문서를 쓰거나, 최근 커밋을 베끼거나, 영어를 섞었다. 지시문은 대화 형식을 거쳐 네 모델 모두에 들어갔다. 다만 이 지시문은 8단계에서 Qwen3.8에 맞춰 고친 것이라, 모델마다 지시문을 고치면 결과가 달라질 수 있다.
  • 요약은 차이가 작았다. 핵심 점수는 0.5~1점 차이였고, 틀린 내용이 없었던 것은 Gemma 4뿐이었다.
  • Tri-21B-Think는 생각을 끌 수 없어 짧은 일에도 오래 걸렸다. 열 문항에 66분이 걸렸고, 둘은 답에 닿지 못했다.
  • 이번 결과는 한 번씩, 노트북의 4비트 파일로 잰 것이다. 채점도 Claude 하나가 했다. 채점자가 채점하며 더한 기준은 커밋 표 밑에 적었다.
