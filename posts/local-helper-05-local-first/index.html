로컬 모델이 먼저 고치고, 못 고치면 클라우드로

4편에서 로컬 모델의 세 줄 요약이 아낀 클라우드 비용은 6~8%였습니다. 이번에는 요약이 아니라 고치는 일 자체를 로컬 모델에게 먼저 맡기고, 못 고친 것만 클라우드로 넘기면 얼마나 아끼는지 봅니다.

올린 날
2026-11-27
읽는 시간
약 7분

이번에 할 일

4편에서 Claude Code(Sonnet 5.5)는 고장 하나를 12초쯤에 고쳤고, 로그를 파일로 받을 때 한 번에 $0.064가 들었습니다. 로컬 모델의 세 줄 요약을 더해도 아낀 몫은 6~8%였습니다.

이번에는 순서를 바꿉니다. 같은 고장을 로컬 모델이 먼저 고치게 하고, 고치지 못한 것만 클라우드로 넘깁니다. 로컬이 다 고치면 클라우드 비용은 0입니다. 대신 얼마나 기다려야 하는지를 봅니다.

시험 방법

  • 에이전트는 같은 Claude Code다. Ollama 4편처럼 Claude Code 2.1.326을 Mac mini의 Ollama 0.40.16에 바로 붙였다. ollama launch claude가 넣는 설정을 그대로 쓰고, 클라우드 로그인 정보는 넘기지 않았다.
  • 모델은 Mac mini(M4, 24GB)의 둘이다. Qwen3.6 35B와 Qwen3.8 27B다. Ollama 4편에서 본 대로, 바로 붙이면 생각을 끌 수 없다.
  • 기억할 글 길이는 32,768토큰이다. 이 Mac mini의 Ollama가 평소 쓰는 설정 그대로 두고, Claude Code에도 같은 값을 알려 줬다. 한 번에 쓰는 답은 4,096토큰, 최대 40턴, 30분 제한이다.
  • 고장과 지시문은 4편의 「로그 파일」 조건과 같다. 작업 폴더에 ci.log를 두고 같은 지시문을 줬다. 도구 여섯 개, 샌드박스, 막힌 네트워크도 같다. 모델마다 고장 여섯 개를 두 바퀴, 모두 24번이다.
  • 판정은 빌드로 했다. 실행이 끝나면 npm run build를 다시 돌려, 통과하면 로컬이 고친 것으로, 아니면 Sonnet에게 넘길 것으로 셈했다. 고친 내용은 diff로 하나씩 봤다.
  • 넘길 때는 치우지 않았다. 로컬이 실패하며 남긴 변경을 되돌리지 않고 그대로 Sonnet에게 넘겼다. 아무것도 바꾸지 않고 실패한 경우는 4편의 「로그 파일」 결과와 같으므로 그 값을 썼다.

결과

모델 고침 30분 넘김 평균 시간 턴
Qwen3.6 12/12 0 6.9분 13.4
Qwen3.8 9/12 5 25.8분 10.6
Sonnet 5.5 12/12 0 12.2초 7.4

Sonnet 5.5 줄은 4편의 「로그 파일」 결과입니다. 시간은 Claude Code를 띄워서 끝날 때까지이고, 30분에 끊은 실행은 30분으로 셈했습니다. 턴은 끝까지 간 실행만 평균했습니다.

로컬이 먼저 하고 못 고친 것만 Sonnet에게 넘기면 이렇게 됩니다.

방식 클라우드 비용 걸린 시간
Sonnet만 $0.771 2.4분
Qwen3.6 먼저 $0 1시간 22분
Qwen3.8 먼저 $0.202 5시간 10분

고장 12번을 고치는 데 든 합계입니다. 클라우드 비용은 4편처럼 Claude Code가 API 정가로 셈한 값이고, 로컬 모델에 든 전기는 재지 않았습니다.

Qwen3.6은 다 고쳤지만 7분씩 걸렸다

Qwen3.6은 12번 모두 빌드가 통과하게 고쳤습니다. diff를 보면 10번은 고장을 심기 전과 똑같이 돌려놓았습니다. 빠진 머리말 칸에 글 요약을 새로 써야 하는 2번 고장 두 번만 새 문장이 들어갔는데, 그 문장에는 틀린 곳이 있었습니다. 아래 「빌드가 거르지 못한 것」에서 다룹니다.

시간은 달랐습니다. 한 번에 4.5~9.4분, 평균 6.9분이 걸렸습니다. 턴은 평균 13.4번으로 Sonnet의 두 배 가까이였고, 한 턴에 평균 33초쯤 걸렸습니다. Sonnet이 12초에 끝내는 일을 34배쯤 기다린 셈입니다.

빌드로 판정한 덕을 본 경우도 있었습니다. 1번 고장은 두 번 다 고치고 나서 이런 문구로 끝났습니다.

고친 파일과 원인을 알려 달라는 답은 없었고, 종료 코드도 1이었습니다. 답만 보고 판정했다면 이미 고친 두 번을 Sonnet에게 넘겨, 클라우드 비용이 $0.130 들었을 것입니다. 넘길지는 답이 아니라 빌드로 정해야 했습니다.

32K 가운데 Claude Code가 쓴 것은 절반이었다

위 문구는 대화가 요약할 문턱을 넘어 Claude Code가 대화를 요약했는데, 요약한 뒤에도 금세 다시 넘친 것이 세 번 되풀이됐다는 뜻입니다. 실행 기록을 세어 보니 로컬 실행 24번이 모두 대화를 1~3번 요약했습니다. Sonnet 실행 62번(4편의 60번과 아래에서 넘겨받은 2번)은 한 번도 요약하지 않았습니다.

까닭은 두 가지가 겹친 데 있었습니다.

  • Claude Code는 길이의 절반쯤에서 요약을 시작했다. 대화가 1만 5천 6백 토큰쯤을 넘으면 요약했다. 알려 준 길이 32,768에서 1만 7천쯤을 뺀 값이다. 기억할 글 길이를 49,152로 둔 Ollama 4편에서는 3만 2천 토큰 안팎이었으니, 거기서도 1만 7천쯤을 남겨 두고 요약했다.
  • 로컬 모델은 로그를 통째로 읽었다. 첫 요청은 시스템 프롬프트와 도구 설명, 지시문만으로 7,800토큰쯤이었다. Qwen3.6은 12번 모두, Qwen3.8은 12번 가운데 8번 ci.log를 처음부터 끝까지 열었다. 로그만으로 1만 2천 토큰쯤이 더해져 대화가 2만 1천 토큰 안팎이 됐다. 4편의 Sonnet은 12번 모두 grep으로 오류 줄 주변만 골라 읽었다.

로그를 읽은 요청 하나로 문턱을 훌쩍 넘었고, Qwen3.6은 12번 가운데 11번이 그 요청 바로 뒤에 요약을 시작했습니다. 요약 한 번에 Qwen3.6은 1~3분, Qwen3.8은 4~11분이 걸렸고, 요약에 든 시간이 전체 실행 시간의 절반 가까이(45%, 48%)였습니다.

Qwen3.8은 메모리가 넘쳤다

Qwen3.8은 12번 가운데 다섯 번이 30분 제한에 걸렸습니다. 그 가운데 두 번은 이미 고쳐 둔 채 끝내지 못한 것이라 빌드로는 고친 것으로 셌고, 세 번은 고치지 못했습니다. 끝까지 간 실행도 16~30분이 걸렸습니다.

Ollama가 알려 준 올라간 크기를 보니 Qwen3.8은 기억할 글 길이 32K에서 25.6~29.4GB였습니다. 이 Mac mini의 메모리 24GB를 같은 단위로 세면 25.8GB이니, 메모리 전부와 맞먹거나 넘었습니다. 운영체제와 다른 서비스가 쓸 자리는 남지 않았습니다. Qwen3.6은 17.7GB였습니다.

모델 올라간 크기 실행 뒤 스왑 한 턴
Qwen3.6 17.7GB 0.8GB 33초
Qwen3.8 25.6~29.4GB 6.5~12.5GB 135초

한 턴은 실행마다 걸린 시간을 턴 수로 나눈 값의 평균입니다. Qwen3.6을 돌리는 동안 스왑은 0.8GB 그대로였고, Qwen3.8로 바뀌자 6.5~12.5GB로 늘었습니다. 다음 응답이 나오기까지 15분을 기다린 적도 있었는데, 그 가운데 10분은 대화 요약이었습니다.

다만 이것만으로 메모리 탓이라고 하기는 어렵습니다. 2편과 3편에서 코드와 결함을 가장 잘 찾았던 Qwen3.8은, 대화가 짧아 메모리가 넘치지 않던 그때도 Qwen3.6보다 5배쯤 느렸습니다. 이번에 한 턴이 4배쯤 느렸던 것과 크게 다르지 않습니다. 메모리를 넘긴 것이 얼마나 더 늦췄는지는 가르지 못했습니다. 길이를 줄이면 메모리는 들어가겠지만, 위에서 본 대로 Claude Code가 쓸 수 있는 대화가 더 줄어듭니다.

잘못 고친 채 넘겨받은 Sonnet

Qwen3.8이 고치지 못한 세 번 가운데 두 번은 아무것도 바꾸지 않고 끝났습니다. 나머지 한 번은 5번 고장에서 없는 칸 published뿐 아니라 맞게 쓰여 있던 pubDate까지 역시 없는 칸 publishedAt으로 바꿔 놓은 채 30분에 끊겼습니다.

이 상태 그대로 Sonnet에게 두 번 넘겼습니다. 두 번 모두 첫 명령에서 git status로 남은 변경을 보고, 12초쯤에 pubDate로 바르게 고쳤습니다. 비용은 $0.060과 $0.068로, 4편에서 깨끗한 상태로 받은 같은 고장($0.069, $0.079)보다 비싸지 않았습니다.

빌드가 거르지 못한 것

빌드 통과로 판정하면 놓치는 것도 있었습니다.

  • 새로 쓴 글의 오타와 틀린 내용. 2번 고장은 빠진 머리말 칸에 글 요약을 새로 써야 고쳐진다. Qwen3.6이 쓴 두 개 가운데 하나에는 「견준」이 「견룬」으로 적혀 있었다. 다른 하나는 커밋 메시지와 코딩을 한데 묶어 「EXAONE이 유일하게 하나라도 풀었다」고 썼다. 원 글에서 EXAONE이 푼 것은 코딩 과제이고, 커밋 메시지는 국산 모델 넷 모두 하나도 맞히지 못했다. 빌드는 둘 다 통과했다. Sonnet이 쓴 열 개는 내용도 원 글과 맞았다.
  • 커밋하지 말라는 지시를 어겼다. Qwen3.6은 한 번, 고친 뒤 커밋을 네 번 시도했다. Git 사용자 정보가 없다는 오류가 나자 Git 설정 파일을 고치려 했고, 홈 폴더 이름으로 작성자 이름을 지어 넣기도 했다. 저장소의 설정 파일은 샌드박스가, 홈 폴더의 설정 파일은 Claude Code의 권한 확인이 막았다. 작성자를 넣은 커밋 명령은 대화 없이 돌리는 Claude Code가 승인이 필요하다며 거절했다. 모델이 멈춘 것이 아니라 환경이 막았다.
  • 하지 않아도 될 명령. Qwen3.6은 한 번 npm install을 돌렸다. 이미 설치돼 있어 바뀐 것은 없었다. Qwen3.8은 두 실행에서, 작업 폴더 옆의 다른 폴더에 있지도 않은 ci.log를 모두 네 번 열려 했다.

Sonnet 실행 62번에는 커밋 시도도, npm install도 없었습니다.

셈

고장 하나에 아끼는 클라우드 비용은 $0.064, 6센트쯤입니다. Qwen3.6이 먼저 하면 이 6센트를 아끼려고 7분쯤을 기다립니다. 구독으로 쓴다면 돈이 아니라 사용 한도를 그만큼 아낍니다.

로컬 모델 없이 가장 싼 방법은 4편에서 본 대로 Sonnet에게 로그 없이 「배포가 실패했다」고만 하는 것이었고, 한 번에 $0.053이었습니다. 그것과 견줘도 아끼는 몫은 고장 하나에 5센트쯤입니다.

Qwen3.8을 먼저 쓰면 12번에 $0.20를 클라우드에 쓰고 5시간을 기다립니다. 이 Mac mini에서는 고를 까닭이 없습니다.

알게 된 것

  • 로컬이 먼저 하면 클라우드 비용을 다 아낄 수도 있었다. Qwen3.6은 작은 고장 12번을 모두 빌드가 통과하게 고쳐, 클라우드에 하나도 넘기지 않았다.
  • 대신 34배쯤 느렸다. 고장 하나에 Sonnet은 12초, Qwen3.6은 6.9분이었다. 바로 고쳐야 하는 배포 실패라면 기다릴 값이 없다. 자리를 비우는 동안 돌려 두거나, 클라우드 사용 한도가 빠듯할 때 쓸 만하다.
  • 넘길지는 빌드로 정한다. 답과 종료 코드만 보면 이미 고친 것까지 넘긴다.
  • 32K는 Claude Code에게 절반이었다. 1만 7천 토큰쯤을 남겨 두고 요약하니, 로컬 실행은 24번 모두 대화를 요약했고 그 시간이 전체의 절반 가까이였다. 로그를 통째로 읽은 20번은 그 요청 하나로 문턱을 넘었다.
  • 24GB에 Qwen3.8 27B와 32K는 넘쳤다. 올라간 크기가 25.6~29.4GB였고 스왑이 늘었다. 다섯 번이 30분 제한에 걸렸지만, 메모리가 얼마나 늦췄는지는 가르지 못했다.
  • 잘못 고친 채 넘겨도 Sonnet은 정리했다. 남은 변경을 먼저 보고 바르게 고쳤고, 비용도 더 들지 않았다.
  • 빌드 통과가 전부는 아니다. 새로 쓴 글의 오타와 틀린 내용은 빌드가 거르지 못했고, 지시를 어긴 커밋은 샌드박스와 권한 설정이 막았다. 로컬 에이전트는 막힌 환경 안에서 돌리고, 고친 결과는 한 번 봐야 한다.
