웹 검색 붙이기

6단계에서 붙인 웹 UI의 모델은 학습이 끝난 시점까지만 압니다. 오늘이 며칠인지도 모릅니다. 이번에는 직접 띄우는 검색 서버 SearXNG를 붙여, 웹 검색을 켠 질문은 인터넷에서 찾은 결과를 읽고 답하게 합니다. 검색 엔진을 고르고, 설치하고, 웹 UI를 설정한 뒤, 날씨 질문으로 시험합니다.

올린 날
2026-11-16
읽는 시간
약 10분

이번에 할 일

  1. 검색 엔진을 고른다. 질문에서 나온 검색어가 어느 검색 엔진으로 나가는지 정하는 일이라 먼저 정한다.
  2. 검색 서버를 Mac mini에 띄운다. 웹 UI가 부를 검색 창구를 Mac mini 안에 둔다.
  3. 웹 UI에 연결한다. 검색어는 모델이 만들고, 검색 결과는 요약만 답에 넣는다.
  4. 날씨 질문으로 시험한다. 오늘의 정보가 없으면 답할 수 없는 질문이다.

왜 웹 검색인가

처음 시험에서 「금주 안양 날씨 알려줘」라고 물었습니다. Mac mini 모델은 실시간 날씨를 볼 수 없다면서 「2024년 5월 기준」이라고 하더니, 5월 중순의 날씨를 늘어놓았습니다. 오늘은 11월 16일입니다.

모델이 아는 것은 학습이 끝난 시점까지입니다. 그 뒤의 일도, 오늘이 며칠인지도 모릅니다. 그래서 날씨, 뉴스, 가격, 최신 버전처럼 지금의 정보가 필요한 질문에는 인터넷에서 찾은 결과를 함께 넣어 줘야 합니다.

검색 엔진 고르기

처음에는 DuckDuckGo 하나만 쓰려고 했습니다. 가입하거나 API 키를 받지 않아도 되기 때문입니다. API 키는 서비스에 요청할 때 함께 보내는 비밀 문자열입니다. 그런데 Mac mini에서 보낸 검색에는 결과가 하나도 오지 않았습니다. 그래서 다른 길을 견줘 봤습니다.

방법 결과
DuckDuckGo 프로그램이 보낸 검색에 사람인지 확인하는 응답(202)만 돌려줬다. 몇 시간 뒤에 다시 해도 같았다
Bing 결과 페이지 읽기 결과는 왔다. 하지만 사람이 보는 결과 페이지를 프로그램이 읽는 방식이라, DuckDuckGo처럼 언제 막힐지 모른다
공식 검색 API (Tavily, Brave) 프로그램이 쓰라고 내준 창구라 안정적이다. 대신 가입하고 API 키를 받아야 하고, 곳에 따라 카드도 등록해야 한다
SearXNG 직접 띄우는 메타 검색 서버. API 키 없이 검색어를 여러 검색 엔진에 보내고 결과를 모은다

DuckDuckGo의 사람 확인을 피하려고 브라우저인 척하는 방법은 쓰지 않았습니다. 상대가 막아 둔 것을 우회하는 일이기 때문입니다.

고른 것은 SearXNG입니다. 메타 검색은 여러 검색 엔진의 결과를 모아 보여 주는 검색입니다. 한 엔진이 막아도 다른 엔진의 결과로 답할 수 있습니다. 가입이나 API 키도 필요 없고, Open WebUI의 검색 엔진 목록에 들어 있어서 고른 뒤 주소만 넣으면 연결됩니다.

구조

부분 하는 일 어디에
Open WebUI 모델에게 검색어를 만들게 하고, 검색하고, 결과를 모델에게 넘긴다 Mac mini 3000번 포트 (6단계)
SearXNG 검색어를 여러 검색 엔진에 보내고 결과를 모은다 Mac mini 8888번 포트, 바깥에서는 들어올 수 없음
모델 검색어를 만들고, 결과를 읽고 답한다 Mac mini의 MLX 서버, 노트북의 llama.cpp 서버

포트는 한 기계 안에서 프로그램마다 나눠 받는 접속 번호입니다. SearXNG는 Mac mini 안에서만 받게 해서, 사람들은 Open WebUI를 거쳐서만 검색할 수 있습니다.

SearXNG 설치

SearXNG는 보통 컨테이너로 띄웁니다. 하지만 Mac mini에는 컨테이너 도구가 없습니다. 컨테이너를 돌릴 가상 머신을 띄우면 모델이 쓸 메모리를 그만큼 빼앗깁니다. 그래서 Python으로 직접 설치했습니다. 5단계처럼 uv를 썼고, 설치 크기는 약 110MB입니다.

설정 파일에서 기본값과 다른 것은 두 가지뿐입니다. 비밀 값 secret_key와, Open WebUI가 결과를 받는 JSON 형식입니다. 나머지 줄은 기본값과 같은 값을 눈에 보이게 적어 둔 것입니다. 아래 주석은 설명을 위해 한국어로 옮겼습니다.

서버 프로그램은 공식 컨테이너와 같은 granian입니다. 시작 스크립트 ~/llm-service/start-searxng.sh가 띄우고, 메모리는 약 190MB를 씁니다. 띄운 뒤 Mac mini 안에서 직접 검색해 봤습니다.

DuckDuckGo는 여기서도 사람 확인을 내밀었습니다. SearXNG는 그 엔진을 알아서 빼고, Brave와 Google의 결과로 답했습니다.

관리자 패널의 설정과 모델 편집 화면에서 아래 값을 바꿨습니다. 이번에는 Open WebUI 데이터베이스를 백업한 뒤 같은 값을 직접 넣고 웹 UI를 다시 켰습니다. 처음 설치할 때를 위해 같은 값을 시작 스크립트의 환경 변수에도 적어 두었습니다.

모델 편집 시스템 프롬프트 아래 아래 「오늘 날짜를 모른다」

막힌 곳 두 가지

1. 스위치를 켜도 검색하지 않았다

웹 검색 스위치를 켜고 물었는데, 받은 답이 위의 「2024년 5월 기준」이었습니다. 노트북 모델도 마찬가지였습니다. 기록을 보니 검색 자체가 없었습니다.

  • 모델이 읽은 입력이 18토큰, 질문 한 줄뿐이었다.
  • 답에 붙은 출처가 0개였다.
  • 웹 검색을 하면 먼저 가야 할 「검색어 만들기」 요청이 모델 서버에 오지 않았다.

원인은 Open WebUI 0.13.3의 함수 호출 방식이었습니다. 함수 호출은 모델이 검색 같은 도구를 쓰게 하는 방식이고, 두 가지가 있습니다.

방식 웹 검색 스위치를 켜면
네이티브 (기본값) 웹 UI는 검색하지 않는다. 모델이 스스로 검색 도구를 부르기를 기다린다
레거시 웹 UI가 먼저 검색하고, 결과를 질문과 함께 모델에게 넘긴다

6단계에서 모델의 「내장 도구」를 껐습니다. 켜 두면 짧은 질문에도 도구 설명이 붙어 7,226토큰이 됐기 때문입니다. 그래서 모델에게는 부를 검색 도구가 없었고, 네이티브 방식에서는 아무도 검색하지 않았습니다. 두 모델의 함수 호출을 레거시로 바꾸자 바로 검색했습니다. Open WebUI 코드를 봐도, 답하기 전에 검색하는 부분은 함수 호출이 레거시일 때만 실행됩니다.

스위치는 켜졌는데 아무 일도 없을 때

화면에는 스위치도 지구본도 정상으로 보이고, 오류도 나지 않습니다. 답 위에 「N개의 소스 검색됨」이 없으면 검색하지 않은 것입니다. 내장 도구를 끈 모델이라면 함수 호출이 레거시인지 먼저 확인하세요.

2. 오늘 날짜를 모른다

검색 결과가 없으면 모델은 오늘 날짜를 모릅니다. 그래서 학습한 무렵인 「2024년 5월」을 오늘로 짐작했습니다. 두 모델의 시스템 프롬프트에 두 문장을 넣었습니다. 시스템 프롬프트는 모든 대화 앞에 붙는 지시문입니다.

{{CURRENT_DATE}}와 {{CURRENT_WEEKDAY}}는 Open WebUI가 질문을 보낼 때마다 오늘 날짜와 요일로 바꿔 넣습니다. 이 두 문장 때문에 질문마다 입력이 80토큰쯤 늘었습니다. Mac mini에서 1초 남짓입니다. 검색 결과가 없을 때는 이제 짐작하지 않고 웹 검색을 켜라고 안내합니다.

쓰는 법

함께 쓸 사람에게는 이 단락을 보내면 됩니다.

  1. 입력창 왼쪽 + 버튼을 누르고, 메뉴 맨 아래 웹 검색 스위치를 켭니다.
  2. 입력창에 파란 지구본이 생기면, 그 메시지는 검색해서 답합니다.
  3. 답 위에 「13개의 소스 검색됨」처럼 찾은 결과 수가 나오고, 문장 끝에는 출처가 붙습니다.

알아 둘 것도 있습니다.

  • 스위치는 메시지마다 켭니다. 검색하면 더 오래 걸리니, 날씨, 뉴스, 가격, 최신 버전처럼 지금의 정보가 필요할 때만 켜세요.
  • 검색어는 바깥 검색 엔진으로 나갑니다. 질문 전체가 아니라 모델이 만든 검색어지만, 질문에 밖에 알리면 안 되는 이름이나 숫자가 있으면 검색어에 섞일 수 있습니다. 그런 질문에는 웹 검색을 켜지 마세요.
  • 「+ → Add Context → 웹페이지 첨부」에도 지구본이 있습니다. 주소를 직접 넣어 페이지 하나를 붙이는 다른 기능입니다.

두 모델로 시험

웹 검색을 켜고 「금주 안양 날씨 보고」를 두 모델에 물었습니다.

  • Qwen은 느리지만 질문을 더 잘 알아들었다. 「금주」를 보고 검색어를 세 갈래로 나눴고, 날짜별로 정리했다. Gemma는 검색어 하나로 오늘 날씨만 답했다.
  • Mac mini 시간의 대부분은 읽기와 쓰기다. 검색 자체는 1~3초였다. 결과 요약 13개가 2,500토큰이 넘어서, 읽는 데만 39초가 걸렸다.
  • 검색어를 만들 때 지난 대화도 같이 읽는다. Mac mini는 앞서 받은 긴 답까지 806토큰을 읽느라 13초를 썼다. 새 채팅에서 물으면 더 짧다.
  • 출처마다 숫자가 조금씩 다르다. 오늘 최저 기온을 Gemma는 7°, Qwen은 8°로 답했다. 서로 다른 출처를 읽었기 때문이다. 중요한 숫자는 출처를 눌러 확인하는 게 좋다.

검색어는 어디로 가나

  • 웹 검색 스위치를 켠 메시지만 검색합니다.
  • 밖으로 나가는 것은 모델이 만든 검색어입니다. 위의 「안양 금주 날씨 예보」 같은 것입니다.
  • SearXNG가 이 검색어를 Google, Brave, Bing, DuckDuckGo 같은 여러 검색 엔진에 보냅니다. 검색 엔진 쪽에는 이 네트워크가 인터넷에 나갈 때 쓰는 주소가 보입니다.
  • SearXNG 기록에는 검색어가 남지 않고, 오류만 남습니다.
  • 대화와 검색어는 Open WebUI 데이터베이스, 곧 Mac mini 안에만 남습니다.

다음 단계로

이제 웹 UI의 모델은 웹 검색을 켜면 지금의 정보를 찾아 읽고 답합니다. 연재는 다음 8단계에서 이 서버를 제 프로젝트에 실제로 붙여 씁니다. 커밋 메시지 초안을 로컬 모델에게 맡기고 Claude와 비교합니다. 그 밖에 남은 일은 둘입니다.

  • SearXNG 늘 켜 두기: 지금은 손으로 띄워 둔 상태입니다. sudo ~/llm-service/install-searxng.sh 한 줄이면 5단계처럼 Mac mini가 켜질 때 저절로 뜹니다.
  • 제목 생성 끄기 검토: 새 채팅의 첫 질문마다 대화 제목을 만드는 요청이 함께 갑니다. Mac mini는 질문을 한 번에 하나씩 읽어서, 첫 답이 4초 남짓 늦게 시작합니다.
