형식을 정해 주면 국산 LLM도 커밋 메시지를 쓸까

3편에서 국산 모델 넷은 지시문을 받고도 diff를 되풀이하거나 설명 문서를 썼습니다. 이번에는 그 실패에 맞춰 지시문을 고치고, 답을 JSON 틀에 맞춰 받게 해 같은 커밋 일곱 개를 다시 맡겼습니다. 3편에서 돌리지 않은 Mac mini에서도 돌렸습니다.

올린 날
2026-11-23
읽는 시간
약 10분

이번에 할 일

3편에서 국산 모델 넷은 커밋 메시지를 저마다 다른 모양으로 틀렸습니다. Mi:dm 2.0은 diff를 되풀이했고, EXAONE 4.5는 메시지 대신 설명 문서를 썼습니다. Kanana-2는 최근 커밋을 베꼈고, Tri-21B-Think는 영어를 섞었습니다. 3편의 지시문은 지난 연재에서 Qwen3.8에 맞춰 고친 것이라, 3편에서는 지시문을 고치면 결과가 달라질 수 있다고 적었습니다. 이번에 그것을 확인합니다.

  1. 지시문을 고친다. 네 가지 실패를 하나씩 막는 줄을 넣는다.
  2. 답의 틀을 강제한다. Ollama의 구조화 출력(format)으로 답을 JSON {title, body}로만 받는다.
  3. Mac mini에서도 돌린다. 3편은 노트북에서만 돌렸다. Mac mini에서는 3편 지시문까지 세 조건을 모두 돌린다.
  4. 모델 이름과 조건을 가리고 채점한다. 기준은 3편 기준에 한 가지를 더한 것이다.

바꾼 두 가지

고친 지시문

3편 지시문에서 바꾼 곳은 이렇습니다.

  • 할 일을 첫 줄에 밝혔다. diff를 읽고 메시지 하나를 쓴다고 적었다. 설명 문서를 쓰는 실패를 막으려는 줄이다.
  • 「’최근 커밋’의 언어와 형식을 그대로 따른다」를 뺐다. 대신 한국어로 쓰고, 최근 커밋은 말투와 형식만 참고하며 내용은 옮기지 않는다고 적었다. 최근 커밋을 베끼거나 영어로 쓰는 실패를 막으려는 줄이다.
  • diff를 옮겨 적지 말라고 적었다. diff를 되풀이하는 실패를 막으려는 줄이다.
  • 영어 접두어와 앞말, 소제목을 막았다. feat: 같은 접두어를 붙이지 말라고 적고, 쓰지 않을 것에 앞말과 소제목을 더했다.
  • 사용자 말 끝에 한 줄을 붙였다. 3편은 최근 커밋, 바뀐 파일, diff만 보냈다. 이번에는 끝에 「위 변경에 붙일 커밋 메시지를 쓰세요.」를 더했다.

JSON 형식 강제

Ollama의 /api/chat 요청에 format으로 JSON 스키마를 주면, 모델은 그 틀에 맞는 글자만 낼 수 있습니다. JSON 밖에 앞말이나 코드 블록을 붙일 수 없습니다. 다만 title과 body 문자열 안에는 무엇이든 쓸 수 있습니다.

받은 JSON은 「title, 빈 줄, body」로 이어 붙여 메시지로 쳤습니다. 그래서 이 조건에서는 제목 뒤 빈 줄을 빠뜨릴 수 없습니다. 제목 안의 접두어나 본문의 줄 수는 모델이 정합니다.

시험 방법

커밋 일곱 개와 설정은 3편과 같습니다. 온도 0, 기억할 글 길이 16,384토큰, 답은 600토큰까지(Tri-21B-Think는 4,096토큰)이고, 생각은 끌 수 있는 모델이면 껐습니다. 두 기계 모두 Ollama 0.40.16이고, 요청은 Mac mini의 시험 스크립트가 보냈습니다.

기계 조건 모델
노트북 고친 지시문, JSON 여섯
Mac mini 3편 지시문, 고친 지시문, JSON 다섯

노트북(Arc 140V 내장 GPU, 메모리 32GB)의 3편 지시문 결과는 3편에서 받은 답을 다시 매긴 것입니다. Mac mini(M4, 메모리 24GB)에는 국산 모델 넷을 노트북과 같은 태그로 받은 GGUF로, Qwen3.6은 노트북과 같은 GGUF 파일로 올렸습니다. 두 가지가 노트북과 달랐습니다.

  • Gemma 4는 JSON 조건을 돌리지 못했다. Mac mini의 Gemma 4는 Ollama 목록의 gemma4:26b로, Ollama가 MLX 엔진으로 돌린다. 이 엔진은 format이 든 요청에 HTTP 501 structured output is unavailable을 돌려줬다. Mac mini가 웹 UI용으로 늘 쓰는 Qwen3.8도 같은 엔진이라 같은 오류가 났다. 노트북과 같은 Gemma 4 GGUF는 받아지지 않아, Mac mini에서는 Qwen3.6만 해외 모델로 세 조건을 다 돌렸다.
  • EXAONE 4.5는 Mac mini에 다 들어가지 않았다. 66층 가운데 51층(22.1GB 가운데 16.5GB)만 GPU에 올라갔고, 메모리 여유가 6%로 떨어지고 스왑이 4.2GB 찼다. 34분 동안 답을 하나도 내지 못해 시험을 멈췄다.

채점은 3편과 같은 방법으로 했습니다.

  1. 기준을 먼저 정했다. 새 답을 보기 전에 3편의 기준(무엇을 바꿨나, 형식, 왜 바꿨나, 지어낸 것)을 그대로 옮겨 적었다. 3편 채점자가 세운 원칙(diff 되풀이, 영어 메시지, 메시지 대신 설명, 메시지 전에 끊김)에 「최근 커밋을 옮긴 답」 하나를 더해, 이런 답은 메시지로 쓸 수 없는 답으로 봤다.
  2. 이름과 조건을 가렸다. 문항마다 노트북은 답 18개, Mac mini는 14개의 순서를 섞고 글자를 붙였다. 어느 답이 어느 지시문에서 나왔는지도 가렸다.
  3. 기계마다 새 대화의 Claude가 채점했다. 노트북 묶음을 먼저 매겼고, 그 채점자가 채점하며 더한 해석 13가지를 Mac mini 채점자에게도 줬다. 줄 수는 실제 줄바꿈으로 세고, Home:이나 파일 경로처럼 라틴 글자 라벨에 콜론을 붙인 제목은 영어 접두어로 보는 것 등이다. Mac mini 채점자도 해석 10가지를 더했다. 한도에서 끊겼어도 제목과 본문이 있으면 메시지로 보고, 제목만 최근 커밋이고 본문이 diff 문장이면 diff 되풀이로 보는 것 등이다.

3편의 답은 새 답과 섞어 다시 매겼습니다. 「둘 다 맞음」은 모델마다 3편과 같았습니다. 형식이 맞은 답은 Kanana-2와 Mi:dm에서 하나씩 적게 셌습니다. Mi:dm은 더한 원칙 때문에 최근 커밋 제목을 옮긴 답이 쓸 수 없는 답이 됐습니다. 지어낸 것은 최근 커밋에서 옮긴 줄을 하나씩 세는 해석 때문에 Kanana-2가 3편의 8개보다 많은 28개였고, EXAONE 4.5는 17개에서 14개로 줄었습니다. 아래 표의 3편 지시문 칸은 모두 다시 매긴 값입니다.

Kanana-2는 두 기계 모두 형식이 맞은 답이 0, 3, 7개로 늘었습니다. 3편 지시문에서는 「Ok, here is …」 같은 앞말을 붙이거나, 최근 커밋을 옮기거나, 제목을 70자 넘게 썼습니다. 고친 지시문에서도 70자가 넘는 한 줄짜리 답이 남았습니다. JSON에서는 제목과 본문을 나눠 쓰면서 일곱 개 모두 맞았습니다.

JSON이 막지 못한 것도 있었습니다. EXAONE 4.5는 고친 지시문에서 쓰던 코드 블록이 JSON에서 사라졌지만, 제목에 feat:이나 deploy:를 붙이거나 본문에 ’- ’ 줄을 다섯~열두 개 넣어 형식은 하나도 맞지 않았습니다. Mi:dm은 제목을 Home:이나 src/styles/site.css:로 시작했고, 본문을 # 소제목으로 시작한 답도 있었습니다. 틀은 「title과 body」만 정할 뿐, 그 안에 무엇을 몇 줄 쓰는지는 정하지 않습니다.

diff의 주요 변경을 맞게 적은 수입니다. 일부만 맞거나 흐린 답은 넣지 않았습니다. 국산 넷을 더하면 노트북에서 1, 6, 6개로 늘었지만, 모델마다 많아야 일곱 개 가운데 넷이었습니다.

형식이 맞은 답 가운데에도 diff에 없는 내용을 담은 것이 많았습니다. 노트북에서 형식이 맞은 국산 모델의 JSON 답 12개 가운데 7개에 지어낸 내용이 있었고, 내용까지 맞은 것은 3개였습니다. Mac mini는 13개 가운데 8개, 5개였습니다. Kanana-2가 노트북에서 JSON으로 낸 답 하나는 최근 커밋까지 섞었습니다.

이 커밋은 robots.txt와 구조화 데이터를 더한 것입니다. 「첫 공개」와 「이름 장난」은 이 커밋에 함께 보낸 최근 커밋 두 줄의 내용이고, 사이트 설명과 리드 문구는 diff에서 바뀌지 않았습니다. 제목 한 줄, 빈 줄, 본문 한 줄이라 형식은 맞았습니다. JSON 틀이 지어낸 내용을 막지는 못했습니다.

모델마다

  • Kanana-2 30B: JSON에서 형식은 두 기계 모두 7개가 맞았다. 내용이 맞은 것은 노트북 2개, Mac mini 3개였다. 고친 지시문에서는 최근 커밋을 통째로 옮긴 답이 사라졌지만, 일부를 섞은 답은 남았다.
  • Tri-21B-Think: 고친 지시문에서 노트북은 내용이 맞은 답이 0개에서 4개로 늘었다. 하지만 제목 다음 줄에 바로 본문을 써서(빈 줄 없음) 형식이 맞지 않았다. JSON에서는 생각을 쓰지 않고 바로 답했고, 고친 지시문에서는 없던 영어 메시지가 노트북 2개, Mac mini 3개 나왔다. Mac mini에서는 3편 지시문에서 3개, 고친 지시문에서 2개가 생각만 쓰다 4,096토큰 한도에서 끊겼다.
  • EXAONE 4.5: 고친 지시문으로 설명 문서는 사라졌다(3편 7개 → 0개). 대신 영어 접두어와 긴 목록을 써서 형식은 하나도 맞지 않았다. 내용이 맞은 답은 0, 1, 3개로 늘었지만, 지어낸 것도 14, 24, 26개로 늘었다. 답은 노트북에서만 받았다.
  • Mi:dm 2.0 Base: 3편 지시문에서는 두 기계 모두 일곱 개 가운데 여섯을 diff 되풀이로 냈다. 고친 지시문에서 되풀이는 노트북 2개, Mac mini 1개로 줄었지만, 제목을 ’- ’로 시작하거나 영어로 쓴 답이 남았다. JSON에서는 노트북의 되풀이가 사라졌다(Mac mini는 1개 그대로). 지어낸 것은 노트북 16개, Mac mini 12개로 셌는데, 그 가운데 10개씩은 최근 커밋 열 줄을 옮긴 한 답에서 나왔다.
  • Qwen3.6 35B: 고친 지시문이 가장 잘 들었다. 노트북에서 둘 다 맞은 답이 2개에서 6개로 늘었다. Mac mini에서는 4개에서 5개였다.
  • Gemma 4 26B: 노트북에서는 세 조건 모두 7개였다. Mac mini에서는 다른 파일(MLX)로 돌려 3편 지시문에서 5개였다. 하나는 제목에 CI:를 붙였고, 하나는 내용이 틀렸다.

JSON을 강제하자 Tri가 생각을 건너뛰었다

Tri-21B-Think는 생각을 끄는 스위치가 없어, 답 안에 생각을 먼저 쓰고 </think> 뒤에 답을 씁니다. JSON 조건에서는 생각이 0자였고, 답 하나에 걸린 시간의 가운데 값이 노트북 17초, Mac mini 26초였습니다. 고친 지시문에서는 노트북 401초, Mac mini 722초였습니다. format을 주면 첫 글자부터 JSON이어야 하니 생각을 쓸 자리가 없어진 것으로 보입니다. 빨라진 대신 고친 지시문에서는 없던 영어 답이 2~3개 나왔습니다.

두 기계의 답은 같았나

온도 0이라도 두 기계의 답은 대부분 달랐습니다. 같은 모델로 같은 요청을 보냈을 때, 글자까지 같은 답은 이만큼이었습니다.

GPU와 계산 방식이 달라 작은 수치 차이가 생기고, 한 낱말이 갈리면 그 뒤가 모두 달라지는 것으로 보입니다.

같은 답 12개는 두 채점자가 따로 매긴 셈이 됐습니다. 9개는 무엇·형식·왜가 모두 같았고(그 가운데 하나는 지어낸 것이 1개와 0개로 갈림), 3개는 「무엇을 바꿨나」가 한 칸(○와 △, △와 ✕) 달랐습니다. Mac mini에서 Mi:dm이 JSON 조건에서 「둘 다 맞음」을 받은 1개도 그 셋 가운데 하나입니다. 노트북에서는 같은 답이 △였습니다. Mi:dm의 JSON 내용 칸이 노트북 0개, Mac mini 2개로 다른 것도 같은 글에 매긴 값이 달라서 생겼습니다.

EXAONE 4.5 4.4 —

고친 지시문에서 초당 토큰 수의 가운데 값입니다. Mac mini의 Gemma 4는 노트북과 다른 MLX 파일입니다. 한 번에 일부만 계산하는 MoE 모델(Kanana-2, Gemma 4, Qwen3.6)은 Mac mini에서 초당 28~29토큰으로 노트북보다 빨랐습니다. 모든 층을 다 계산하는 Mi:dm 2.0은 두 기계가 비슷했고, Tri-21B는 Mac mini에서 오히려 느렸습니다.

Tri-21B-Think는 Mac mini에서 답 21개(커밋 7개 × 조건 3개)에 3시간 4분이 걸렸습니다. 그동안 Mac mini의 웹 UI 모델 Qwen3.8은 내려가 있었습니다. 시험 스크립트가 모델마다 다른 모델을 모두 내렸고, 서비스도 한 번에 모델 하나만 올리게 해 두었기 때문입니다(Ollama로 다시 돌려 보기 7편). 시험이 끝난 뒤 다시 올렸습니다.

알게 된 것

  • 형식은 JSON으로 나아졌다. Kanana-2는 두 기계 모두 형식이 맞은 답이 0개에서 7개가 됐다. 하지만 EXAONE 4.5는 하나도 맞지 않았다. 제목의 영어 접두어나 본문의 줄 수는 JSON 틀이 막지 못했다.
  • 내용은 조금 늘었지만 적었다. 국산 넷의 내용이 맞은 답은 노트북에서 1, 6, 6개로 늘었지만, 모델마다 많아야 일곱 개 가운데 넷이었다. 「둘 다 맞음」은 많아야 셋이었고, Gemma 4는 일곱 개 모두 맞았다.
  • 형식이 맞으면 틀린 내용을 알아채기 어렵다. 형식이 맞은 국산 모델의 JSON 답 가운데 절반 넘게 diff에 없는 내용이 들어 있었다. 메시지처럼 생겼으니 내용을 따로 읽어야 한다.
  • 고친 지시문은 해외 모델 Qwen3.6에 가장 잘 들었다. 노트북에서 2개가 6개로 늘었다. Mac mini에서는 4개에서 5개였다.
  • Mac mini의 MLX 엔진 모델은 JSON 형식을 받지 못했다. Ollama 0.40.16에서 MLX 엔진으로 도는 두 모델(Gemma 4, Qwen3.8)은 JSON 형식 요청에 HTTP 501을 돌려줬다. 같은 Mac mini에서도 GGUF로 올린 모델은 형식을 받았다.
  • 커밋 메시지는 여전히 Gemma 4에게 맡긴다. 6편의 표에서 「국산이라면」 칸은 이번에도 「아직 없음」이다.
  • 이번 결과는 한 번씩 잰 것이다. 채점도 기계마다 Claude 하나가 했고, 같은 답에서 「무엇을 바꿨나」가 갈린 일이 12개 가운데 3개 있었다.
