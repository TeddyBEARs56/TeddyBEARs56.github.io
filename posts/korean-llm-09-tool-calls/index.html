국산 LLM은 도구를 제대로 부를까

5편에서 국산 모델에게 코딩을 맡겼을 때, 과제를 푼 것은 EXAONE 4.5뿐이었습니다. 다른 모델은 파일을 열지 않고 끝내거나, 도구 호출을 생각 속에 써서 실행되지 않았습니다. 이번에는 코딩을 빼고 도구 호출만 떼어, 어디서 막히는지 가립니다.

올린 날
2026-11-25
읽는 시간
약 6분

이번에 할 일

5편에서 Claude Code를 붙여 코딩 과제를 맡겼을 때, 과제를 푼 국산 모델은 EXAONE 4.5뿐이었습니다. Mi:dm 2.0과 Tri-21B-Think는 대부분 파일을 열지 않고 끝냈고, Kanana-2는 도구 호출을 생각 속에 써서 실행되지 않았습니다. 그런데 실패가 모델의 실력 탓인지, 도구를 부르는 형식 탓인지, 긴 과제 탓인지는 가르지 못했습니다.

이번에는 과제를 아주 작게 쪼갰습니다.

  1. 한 번 부르기. 「이 파일을 읽어 줘」처럼 도구 하나면 되는 요청에 맞는 도구와 인자로 부르나.
  2. 부르지 않기. 도구가 필요 없는 질문에는 도구 없이 답하나.
  3. 결과 읽고 답하기. 도구 결과가 이미 대화에 있을 때 그 결과로 답하나.
  4. 두 단계로 부르기. 첫 도구의 결과를 보고 다음 도구를 골라 부르나.

시험 방법

도구와 가짜 저장소

모든 요청에 도구 다섯 개를 함께 줬습니다. 코딩 에이전트가 쓰는 것과 비슷한 파일 목록(list_files), 파일 읽기(read_file), 글 찾기(grep), 명령 실행(run_command)과 인터넷 검색(web_search)입니다. 도구를 부르면 실제로 실행하지 않고, 이 블로그 저장소를 흉내 낸 결과를 미리 적어 두었다가 돌려줬습니다.

문항 18개

  • 한 번 부르기 6개: 「posts.ts의 30~45번째 줄만 읽어 줘」 같은 요청.
  • 부르지 않기 4개: 「git merge와 rebase의 차이를 설명해 줘」 같은 질문.
  • 결과 읽고 답하기 4개: 파일 내용을 대화에 넣어 준 뒤 「최대 글자 수는?」.
  • 두 단계로 부르기 4개: 「빌드를 돌려 보고, 실패하면 원인 파일을 열어 줘」.

채점은 자동입니다. 기준은 국산 모델의 답을 보기 전에 적었고, 그 전에 Mac mini의 Qwen3.6으로 여섯 문항을 시험 삼아 돌려 채점 코드를 확인했습니다.

  • 한 번 부르기: Ollama가 도구 호출로 알아본 첫 답의 도구 이름과 인자가 맞으면 맞음. 줄 번호는 숫자로 줘야 한다.
  • 부르지 않기: 도구를 부르지 않으면 맞음.
  • 결과 읽고 답하기: 대화에 도구 호출과 결과가 이미 있다. 더 부르지 않고 답에 기대한 값이 나오면 맞음. 확인하려고 한 번 더 불러도 틀린 것으로 셌다.
  • 두 단계로 부르기: 가짜 결과를 돌려주며 다섯 번까지 주고받는다. 필요한 호출을 차례로 하고 그 뒤 답에 기대한 값이 나오면 맞음.

모델과 조건

노트북(Arc 140V 내장 GPU, 메모리 32GB)의 Ollama 0.40.16에서 2~8편과 같은 파일로 돌렸습니다. 요청은 Mac mini의 시험 스크립트가 Ollama 자체 API(/api/chat)로 보냈고, 온도 0으로 문항마다 한 번씩 돌렸습니다.

5편에서 Kanana-2는 Ollama 자체 API로 생각을 끄고 한 번 보냈을 때 도구 호출이 잡히고, 켜면 생각 속에 묻혔습니다(한 번씩이라 단정하지 않았습니다). 그래서 이번에는 모든 모델을 생각 끔과 생각 켬 두 조건으로 돌렸습니다. Claude Code는 생각을 켜고 보냅니다. Ollama가 생각을 지원한다고 알려 준 모델은 Gemma 4, Qwen3.6, Kanana-2, EXAONE 4.5였고, Mi:dm 2.0과 Tri-21B-Think는 생각 스위치가 없어, 두 조건의 답과 도구 호출이 18문항 모두 글자까지 같았습니다.

결과

18문항 가운데 맞힌 수입니다. Tri는 Tri-21B-Think, EXAONE은 EXAONE 4.5, Mi:dm은 Mi:dm 2.0, Kanana는 Kanana-2입니다.

칸의 최대는 차례로 6, 4, 4, 4입니다. Kanana-2의 생각 켬은 부르지 않기 4개를 맞혔지만, 네 문항 모두 답을 생각 속에만 쓰고 보이는 답은 비어 있었습니다. 기준대로 「도구를 부르지 않았으니 맞음」으로 셌을 뿐, 실제로 쓸 수 있는 결과는 18문항 가운데 하나였습니다.

  • 콕 집어 시키면 부른다. Mi:dm 2.0과 EXAONE 4.5는 한 번 부르기 여섯 개를 모두 맞혔고, 줄 번호를 숫자로 주는 문항도 맞혔다. Tri-21B는 다섯 개, Kanana-2는 생각을 끄고도 세 개였다.
  • 부르지 않기는 거의 다 지켰다. 틀린 것은 생각을 끈 EXAONE 4.5가 「빌드가 실패했습니다」를 영어로 옮겨 달라는 말에 echo 명령을 부른 하나였다.
  • 막힌 곳은 두 단계였다. 해외 둘은 넷 가운데 2~4개였고, 국산은 EXAONE 4.5가 2~3개, Kanana-2가 0~2개, Mi:dm 2.0과 Tri-21B가 1개였다. 국산 모델이 두 단계에서 틀린 21번 가운데 13번은 첫 도구조차 부르지 않았다. 결과를 받아 다음을 정하기 전에, 스스로 일을 시작하는 데서 먼저 멈췄다.

모델마다

  • Mi:dm 2.0: 한 번 부르기와 부르지 않기는 모두 맞혔다. 두 단계에서는 셋 모두 되물으며 멈췄다. 빌드 명령을 무엇으로 할지 묻거나, 첫 도구를 부른 뒤 「확인해 드릴까요?」, 「실행해 드릴까요?」라고 허락을 구했다. 결과 읽기에서는 파일에 함께 나온 MAX_PROSE = 24를 「표 칸의 최대 글자 수」로 잘못 읽었다. 5편에서 인용한 대화 틀의 고정 지시문(모호하면 추가 정보를 요청한다)과 이어 볼 수 있지만, 지시문을 빼고 다시 돌려 보지는 않았다.
  • EXAONE 4.5: 국산 가운데 가장 고르게 맞혔다. 결과를 받아 답을 다 쓰고도 「확인하려고」 한 번 더 부른 일이 생각 끔에서 하나, 켬에서 둘 있었다(Qwen3.6도 같은 이유로 두 번 틀렸다). 생각을 켠 두 단계 한 문항은 7분 넘게 돌다가 Ollama가 HTTP 500으로 끊었다.
  • Tri-21B-Think: 생각을 답 안에 쓴다. 한 번 부르기 하나는 도구 호출을 Ollama가 알아보는 모양이 아니라 ```json 코드 블록으로 썼다. 두 단계 셋은 도구를 한 번도 부르지 않았다. 남긴 답의 앞부분에는 무엇을 부를지 계획이 길게 적혀 있었다. 결과 읽기 하나와 두 단계 하나는 한국어로 답하라는 지시와 달리 영어로 답했다.
  • Kanana-2: 생각을 켜면 결과를 읽은 답과 부르지 않기의 답을 모두 생각 속에 썼고, 도구 호출도 일곱 문항에서 생각 속에 글로 썼다. 생각 속 답은 대체로 맞았지만, Ollama는 그것을 생각으로 돌려주고 보이는 답은 비워 두었다. 생각을 끄면 12문항을 맞혔지만, 그때도 네 문항은 도구를 부르지 않았다. 셋은 도구 호출 JSON을 답 글 속에 썼고, 하나는 「Okay, I need to run…」로 시작하는 영어 글을 쓰다 답 한도(2,048토큰)에서 끊겼다. 5편에서 생각을 끄면 풀릴 수 있다고 했던 것이, 이번에는 일부만 풀렸다.

두 단계 문항의 가짜 저장소

두 단계 문항 가운데 「빌드를 돌려 보고…」와 「README.md를 읽고 설치 명령을 실행해 줘」에서는, 먼저 package.json을 읽거나 README.md가 있는지 파일 목록으로 확인한 모델이 있었습니다(생각 켠 Gemma 4의 빌드 문항, Gemma 4와 EXAONE 4.5의 README 문항 하나씩). 가짜 저장소에는 그 결과를 적어 두지 않아 「결과 없음」을 돌려줬고, 그 모델들은 다른 길을 찾다 문항을 놓쳤습니다. 실제 저장소였다면 지나갔을 수 있습니다. 해외 모델의 두 단계 점수는 이만큼 낮게 나왔을 수 있습니다. 국산 모델의 두 단계 실패는 대부분 첫 도구를 부르기 전에 났으므로 이 영향을 받지 않았습니다.

5편과 견주면

5편에서 코딩 과제를 하나도 풀지 못한 Mi:dm 2.0과 Tri-21B도, 「이 파일을 읽어 줘」처럼 콕 집어 시키면 도구를 제대로 불렀습니다. 막힌 것은 스스로 일을 시작해 이어 가는 데였습니다. Mi:dm 2.0은 해도 되는지 되물었고, Tri-21B는 계획만 쓰고 부르지 않았습니다. 코딩 에이전트에게 주는 일은 대부분 이런 열린 일이라, 5편의 결과와 맞습니다. Kanana-2는 이번에도 대화 틀이 열어 둔 생각 속에 쓰는 일이 많아, 생각을 켜고 보내는 Claude Code 같은 도구에 붙이기 어려웠습니다.

18문항에 걸린 시간의 합입니다. EXAONE 4.5의 생각 켬에는 HTTP 500으로 끊긴 문항의 7.4분이 들어 있습니다. 시험하는 동안 노트북에서 웹 UI가 쓰는 모델 서버는 멈춰 두었고, 끝난 뒤 다시 켰습니다.

알게 된 것

  • 콕 집어 시키면 Mi:dm 2.0과 EXAONE 4.5도 도구를 부른다. 한 번 부르기를 모두 맞혔다. 5편의 실패를 이 둘이 「도구를 못 부른다」로 볼 수는 없다. Kanana-2는 이것부터 흔들렸다.
  • 스스로 시작하는 데서 갈렸다. 두 단계는 Qwen3.6이 넷 모두, 국산은 많아야 셋이었고, 국산 모델의 실패는 대부분 첫 도구를 부르기 전에 났다.
  • 대화 틀과 출력 모양이 먼저다. Kanana-2는 생각을 켜면 거의 모든 것을 생각 속에 썼고, Tri-21B는 도구 호출을 코드 블록으로 쓴 일이 한 번 있었다. 모델이 무엇을 할지 알아도, Ollama가 알아보는 모양으로 내지 못하면 실행되지 않는다.
  • 이번 결과는 한 번씩 잰 것이다. 문항은 18개이고 도구 결과는 가짜다. 두 단계 문항 둘은 가짜 저장소에 빠진 결과가 영향을 줬다.
