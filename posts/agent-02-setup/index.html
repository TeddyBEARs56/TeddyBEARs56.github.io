Claude Code를 로컬 모델에 붙이기

11단계의 시험은 Claude Code의 모델만 로컬 모델로 바꿔 돌렸습니다. 이번 글은 그 설정을 순서대로 적습니다. 주소를 바꾸는 것은 환경 변수 몇 줄이지만, 그대로는 요청 형식이 맞지 않고, 기억할 글 길이가 맞지 않고, 첫 요청이 크고, 어떤 모델은 메시지 순서부터 거절했습니다.

올린 날
2026-11-18
읽는 시간
약 10분

이번에 할 일

  1. 주소를 바꾼다. Claude Code가 Anthropic 서버 대신 게이트웨이로 요청을 보내게 한다.
  2. 형식을 바꾼다. 게이트웨이가 Claude 형식 요청을 로컬 모델 서버가 알아듣는 형식으로 바꿔 전하게 한다.
  3. 기억할 글 길이를 알려 준다. 로컬 모델이 담을 수 있는 만큼만 쓰게 한다.
  4. 첫 요청을 줄인다. 요청마다 따라가는 도구 설명을 줄인다.
  5. 대화 형식을 고친다. 메시지 순서를 거절하는 모델을 돌게 한다.
  6. 막아 둔다. 모델이 엉뚱한 명령을 쳐도 인터넷과 설정 폴더에 닿지 못하게 한다.

Claude Code는 2.1.326, 게이트웨이 LiteLLM은 1.106.6입니다. 게이트웨이는 4000번, MLX 서버는 8080번, llama.cpp 서버는 8081번 포트에서 받습니다. Claude 형식은 /v1/messages로, OpenAI 형식은 /v1/chat/completions로 오가는 요청입니다.

1. 주소 바꾸기

Claude Code는 환경 변수를 읽어 어디로, 어떤 API 키로, 어떤 모델 이름으로 보낼지 정합니다. 시험에서는 Claude Code가 Mac mini에서 돌아서 게이트웨이 주소가 127.0.0.1입니다. 다른 컴퓨터에서 쓰려면 Mac mini의 주소(192.168.x.x)를 넣습니다.

  • ANTHROPIC_MODEL에는 게이트웨이에 등록한 이름을 넣는다. Claude Code는 일에 따라 Opus, Sonnet, Haiku 이름을 골라 부르므로, ANTHROPIC_DEFAULT_*_MODEL 셋도 같은 로컬 모델로 돌려 게이트웨이에 없는 이름을 부르지 않게 한다.
  • 기억할 글 길이와 답 길이(CLAUDE_CODE_MAX_*)는 3절에서 설명한다.
  • …_NONESSENTIAL_TRAFFIC는 사용 통계, 업데이트 확인처럼 일과 상관없는 요청을 끈다.
  • …_EXPERIMENTAL_BETAS는 게이트웨이가 모를 수 있는 시험용 기능을 끈다.
  • API_TIMEOUT_MS는 요청마다 서버의 응답이 시작될 때까지 30분을 기다리게 한다(기본 10분). 답이 흘러나오기 시작한 뒤의 시간은 이 값으로 끊지 않는다. Mac mini의 dense 모델은 긴 대화를 읽는 데 오래 걸려서 넉넉히 늘렸다.

Claude Code는 처음 보는 모델 이름을 받으면 오류 출력에 [claude-code:unrecognized_model]을 남깁니다. 경고일 뿐이라 일은 그대로 합니다. 다만 그 모델이 얼마나 긴 글을 담는지 모르므로, 3절에서 직접 알려 줍니다.

2. 게이트웨이가 형식을 바꾸게

Claude Code는 Anthropic의 형식으로 보내고, MLX 서버는 OpenAI 형식만 받습니다. 그래서 두 서버 모두 게이트웨이가 OpenAI 형식으로 바꿔 보내게 했습니다. 9단계에서 세운 게이트웨이 LiteLLM은 Claude 형식 요청을 받아 다른 형식으로 바꿔 전할 수 있습니다. 그런데 openai/로 등록한 모델에는 기본으로 OpenAI의 새 형식인 Responses API(/v1/responses)로 보냅니다. MLX 서버에는 이 주소가 없어서 404가 납니다. 설정 한 줄로 예전 형식(/v1/chat/completions)을 쓰게 했습니다.

  • 모델마다 이름을 하나씩 붙였다. MLX 서버는 요청에 적힌 폴더의 모델을 올리고, 한 번에 하나만 둔다. 이름이 다르면 서버가 모델을 바꿔 끼운다. MLX 서버는 이 컴퓨터 안(127.0.0.1)에서만 받아서 API 키가 없다. 게이트웨이 설정에는 빈 값이 아닌 아무 값(none)을 넣어 둔다.
  • 상태 확인은 껐다. 게이트웨이가 주기적으로 상태를 확인하면 그때마다 모델을 올리기 때문이다.
  • 요청 하나를 30분까지 둔다(timeout: 1800). 게이트웨이 전체의 기본값은 10분(request_timeout: 600)이라 모델마다 따로 늘렸다.
  • 노트북은 이름 하나다(agent-laptop). 노트북은 한 번에 모델 하나만 띄워 두고, 차례가 오면 띄운 모델을 바꿨다.
  • 요청 본문의 extra_body는 버린다. 9단계에서처럼, MLX 서버가 요청 본문의 값으로 다른 모델을 불러오지 못하게 한다.

API 키도 시험용으로 두 개 만들었습니다. Mac mini 시험용과 노트북 시험용입니다. 둘 다 Claude 형식 요청(/v1/messages, /v1/messages/count_tokens)과 모델 목록만 쓸 수 있고, agent-로 시작하는 모델만 부를 수 있고(노트북용은 agent-laptop 하나), 키마다 한 번에 요청 하나만 보낼 수 있습니다. 시험이 끝난 뒤 둘 다 지웠습니다.

3. 기억할 글 길이 알려 주기

Claude Code는 모델이 담을 수 있는 글 길이(컨텍스트)에 가까워지면 지난 대화를 요약해서 줄입니다. 처음 보는 모델 이름이면 이 길이를 100만 토큰으로 여깁니다. 그러면 요약하기 전에 서버가 담을 수 있는 길이를 먼저 넘기므로, CLAUDE_CODE_MAX_CONTEXT_TOKENS로 직접 알려 줘야 합니다. 답 하나에 쓸 길이(CLAUDE_CODE_MAX_OUTPUT_TOKENS)도 정합니다. 정하지 않으면 처음 보는 모델에게는 답 하나에 32,000토큰까지 달라고 합니다.

처음에는 기억할 글 32,768, 답 8,192로 시작했습니다. 그러자 Qwen3.8 27B의 고치기 한 번이 이렇게 흘렀습니다.

요약 요약 전 대화 걸린 시간
첫 번째 11,848토큰 11분
두 번째 11,629토큰 8분
세 번째 11,498토큰 8분

32,768을 알려 줬는데 대화가 1만 1천 토큰대에 이르자 요약했습니다. 답 몫 8,192에 여유분까지 남겨 두고 요약하는 것으로 보입니다. 요약도 모델이 쓰는 글이라, dense 모델에게는 한 번에 8~11분이 걸렸습니다. 세 번째 요약 뒤에 Claude Code는 이 오류를 내고 멈췄습니다. 고친 파일은 맞았지만 42분이 걸렸습니다.

기억할 글을 49,152로 늘리고 답 몫을 4,096으로 줄였습니다. 그 뒤로는 대화가 3만 1천~3만 5천 토큰에 이르러야 요약했습니다. 11단계의 시도 가운데 아홉 번에서 합쳐 12번 요약했고, 한 번에 1~6분이 걸렸습니다.

서버도 같은 길이를 담을 수 있어야 합니다. 노트북의 llama.cpp는 -c 49152로 띄우고, 한 번에 받는 요청 수(-np)는 1로 두어 그 길이를 요청 하나가 다 쓰게 했습니다. Mac mini의 MLX 서버는 미리 정한 길이 없이 대화가 길어지는 만큼 메모리를 더 씁니다. 이 차이는 13단계에서 다룹니다.

4. 첫 요청 줄이기

Claude Code는 요청마다 지시문과 도구 설명을 함께 보냅니다. Mac mini에서 Claude Code가 보내는 첫 요청을 가짜 서버로 받아 Qwen3.8의 토크나이저로 세었습니다. 「hi」 한 마디만 보낸 경우입니다.

설정 도구 첫 요청 그중 도구 설명
기본 12개 11,332토큰 약 7,670토큰
시험에 쓴 설정 6개 7,164토큰 약 3,380토큰
옵션 뜻
-p 대화창 없이 과제 하나를 하고 끝낸다
--max-turns 40 모델이 40번 답하면 멈춘다
--strict-mcp-config 빈 목록({"mcpServers":{}}) 말고는 MCP 서버를 읽지 않는다
--setting-sources project 사용자 설정은 읽지 않고, 작업 폴더의 설정과 --settings로 준 파일만 읽는다
--disable-slash-commands 슬래시 명령과 스킬을 끈다
--tools 명령 실행, 파일 찾기·읽기·고치기·쓰기 여섯 가지만 준다

이게 중요한 까닭은, Claude Code가 답을 받을 때마다 지금까지의 대화를 통째로 다시 보내기 때문입니다. 서버는 앞부분을 기억해 두었다가 다시 쓰는 캐시가 있어야 빠릅니다. Mac mini의 MLX 서버는 캐시를 켜고 상한을 1GB로 정해 두었습니다. 다만 서버 기록에는 캐시가 4.6GB까지 찬 적이 있습니다(13단계). 11단계에서 Qwen3.6 35B-A3B가 Mac mini에서 고치기를 할 때, 21번 답하는 동안 새로 읽은 글은 27,290토큰이고 캐시에서 다시 쓴 글은 308,022토큰이었습니다.

5. 대화 형식 고치기

Devstral Small 2는 첫 요청부터 오류로 끝났습니다. 노트북의 llama.cpp는 이렇게 거절했습니다.

Mac mini에서는 Claude Code가 「There’s an issue with the selected model」이라고만 띄웠습니다. 둘 다 원인은 같았습니다.

  • Claude Code는 첫 요청부터 사용자 메시지 뒤에 시스템 메시지를 하나 더 붙인다. 작업 환경이나 샌드박스 안내 같은 것이다.
  • 게이트웨이는 대화 중간의 시스템 메시지를 사용자 메시지로 바꿔 넘긴다. 그러면 사용자 메시지가 두 번 연달아 간다.
  • Devstral의 대화 형식(chat template)은 사용자와 모델이 번갈아 말하는지 검사한다. 연달아 오면 오류를 낸다.

그래서 대화 형식 파일을 복사해 그 검사 한 줄만 뺐습니다. 메시지를 모델의 입력으로 펼치는 부분은 그대로 두었습니다.

엔진 고친 방법
Mac mini MLX 모델 폴더를 하나 더 만들어, 대화 형식 파일은 고친 사본으로, 토크나이저 설정은 같은 내용의 사본으로 두고, 나머지는 원래 파일을 가리키는 링크로 채웠다. 게이트웨이에는 이 폴더를 새 이름으로 등록했다
노트북 llama.cpp 고친 파일을 --chat-template-file devstral-agent.jinja로 줬다

그 뒤로 Devstral은 결과물을 Mac mini에서 6번, 노트북에서 7번 맞게 만들었습니다(11단계). 검사를 뺐으니 모델은 학습 때 드물었을 순서를 받습니다. 이번 시험에서는 그 때문에 생긴 문제는 보지 못했습니다. 다른 모델들은 원래 대화 형식으로 그대로 돌았습니다.

6. 막아 두기

로컬 모델은 엉뚱한 명령을 칠 수 있습니다. 그래서 Claude Code의 샌드박스를 켜고, 읽으면 안 되는 곳을 막았습니다. 샌드박스는 Claude Code가 실행하는 명령을 운영체제 수준에서 가둡니다.

  • 인터넷은 막았다. 허용한 도메인이 없다. 블로그 빌드에 필요한 패키지는 사본에 미리 깔아 두었다.
  • API 키와 SSH 키가 있는 폴더는 명령으로도, 파일 읽기 도구로도 읽지 못한다. 서버 설정, 기록, Claude Code 자신의 폴더도 같다. 샌드박스의 denyRead는 명령에만 듣고, Read 같은 파일 도구는 permissions.deny로 따로 막아야 한다. 모델 폴더는 명령에서만 막았다.
  • Claude Code에 넘긴 API 키는 명령 안에서 보일 수 있다. 환경 변수는 Claude Code가 실행하는 명령에도 이어진다. 그래서 그 키가 할 수 있는 일을 2절처럼 좁혀 두었다.
  • 샌드박스를 못 켜면 시작하지 않는다. failIfUnavailable이다. 샌드박스 밖에서 명령을 실행하는 길도 닫았다.
  • 파일 고치기는 묻지 않는다. --permission-mode acceptEdits라, 혼자 끝까지 갈 수 있다. 과제마다 새 사본에서 시작해서, 망가져도 다음 과제에 번지지 않는다.

서버 쪽 설정

엔진 설정 뜻
MLX --host 127.0.0.1 이 컴퓨터 안에서만 받는다. API 키는 없다
MLX --chat-template-args '{"enable_thinking":false}' 생각(추론)을 끄게 한다
MLX --prompt-cache-bytes 1073741824 캐시 상한을 1GB로 정한다. 실제로는 넘었다(13단계)
llama.cpp --host 0.0.0.0 --api-key-file <파일> 같은 네트워크에서 받되 API 키를 요구한다

llama.cpp --reasoning-budget 0 생각(추론)을 끄게 한다
llama.cpp -ngl 99 모든 층을 GPU에 올린다

생각을 끄는 방법은 엔진마다 다릅니다. 노트북의 Gemma는 이 설정에도 생각했습니다(11단계).

알게 된 것

  • 주소는 환경 변수로 바뀐다. 형식은 게이트웨이가 바꾼다. 다만 LiteLLM은 설정 한 줄을 더해야 MLX 서버가 받는 형식으로 보낸다.
  • 기억할 글 길이는 꼭 알려 준다. 32,768과 답 8,192로는 1만 1천 토큰대에서 요약했고, 요약 한 번에 8~11분이 걸렸다.
  • 답 몫도 정한다. 처음 보는 모델에게 Claude Code는 답 하나에 32,000토큰까지 달라고 한다. 두 설정 모두 요약은 기억할 글 길이에서 답 몫과 1만~1만 4천 토큰쯤을 뺀 자리에서 일어났다. 두 값을 함께 바꿔서, 답 몫만의 효과는 따로 재지 않았다.
  • 도구를 줄이면 첫 요청이 4천 토큰 준다. 기본 11,332토큰, 시험 설정 7,164토큰이다. 매번 대화를 통째로 다시 보내므로 서버 캐시도 켠다.
  • 대화 형식이 엄격한 모델은 Claude Code의 메시지 순서를 거절할 수 있다. Devstral은 검사 한 줄을 빼야 돌았다.
  • 샌드박스만으로는 파일 읽기 도구를 막지 못한다. 읽으면 안 되는 폴더는 permissions.deny에도 적는다.

다음 글
