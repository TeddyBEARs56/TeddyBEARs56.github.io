MLX, GGUF, Ollama는 무엇이 다른가

로컬 LLM을 깔려고 찾아보면 「MLX 버전」, 「GGUF 파일」, 「Ollama로 설치」 같은 말이 섞여 나옵니다. 셋 중 하나를 고르는 것처럼 보이지만, 사실은 층이 다른 이름입니다. 이 글은 셋이 무엇이고 어떻게 엮이는지, 그리고 이 블로그의 Mac mini와 노트북에서 직접 써 보며 잰 장단점을 정리합니다.

셋은 층이 다르다

이름 무엇인가
GGUF 모델 파일 형식. 파일 하나에 압축한 숫자와 토크나이저, 대화 형식까지 담는다
MLX 애플이 만든 Apple Silicon용 계산 틀. 모델은 MLX 형식 폴더로 받는다
Ollama 모델을 내려받고, 띄우고, API로 내주는 프로그램

엔진이라는 말로 정리하면 이렇습니다. 엔진은 모델 파일을 읽어 실제로 계산하는 프로그램입니다.

  • GGUF 파일은 llama.cpp가 돌린다. llama.cpp는 이 형식을 만든 오픈소스 엔진이다. llama-server를 띄우면 OpenAI 형식 API를 내준다.
  • MLX 형식은 MLX가 돌린다. 파이썬 도구 mlx-lm이 모델을 읽고, mlx_lm.server가 OpenAI 형식 API를 내준다.
  • Ollama는 둘 다 쓴다. 안에 llama.cpp 계열 엔진과 MLX 엔진을 품고, 모델 형식에 따라 고른다. 사용자는 엔진을 몰라도 모델 이름만으로 받고 띄운다.

GGUF와 llama.cpp

이 블로그에서는 지난 연재 2단계에서 llama.cpp를 직접 조립해 처음 모델을 돌렸습니다. 노트북은 지금도 llama.cpp 서버로 웹 UI의 모델을 내주고 있습니다.

  • 어디서나 돈다. Mac에서는 Metal, 노트북의 인텔 GPU에서는 Vulkan과 SYCL, GPU가 없으면 CPU로 돈다. 지난 연재 3단계에서 노트북의 엔진 네 가지를 견줬다.
  • 파일 하나라 다루기 쉽다. 압축 단계도 여럿이라(Q4_K_M, IQ4_XS 등) 메모리에 맞춰 고를 수 있다.
  • 기억할 글 자리를 처음에 잡는다. 띄울 때 -c로 정한 길이만큼 대화 기억 자리를 잡고, 그 안에서 쓴다. 코딩 에이전트 시험에서 노트북은 36번 돌리는 동안 한 번도 멈추지 않았다.
  • Mac에서는 MLX보다 느렸다. 같은 Mac mini에서 Gemma 4 26B의 답 쓰기가 초당 27토큰으로, MLX의 40토큰보다 느렸다.
  • 설정이 많다. 기억할 글 길이(-c), 동시에 받는 요청 수(-np), GPU에 올릴 층 수(-ngl) 등을 직접 정해야 한다. 너무 크게 잡으면 띄우거나 첫 계산에서 막힌다.

MLX

MLX는 애플이 Apple Silicon에 맞춰 만든 계산 틀입니다. CPU와 GPU가 한 메모리를 함께 쓰는 구조(통합 메모리)를 전제로 합니다. 모델은 Hugging Face의 mlx-community 같은 곳이 MLX 형식으로 바꿔 올린 것을 받아 씁니다. 지난 연재 3단계부터 Mac mini의 늘 켜 둔 서버가 MLX입니다.

Mac mini에서 llama.cpp MLX
Gemma 4 26B, 답 쓰기 초당 27.03토큰 초당 40.46토큰
Qwen 3.8 27B, 답 쓰기 초당 6.29토큰 초당 6.91토큰
  • Mac에서 빠르다. 답 쓰기가 Gemma는 50%, Qwen은 10% 빨랐다. 질문 읽기는 3~7% 빨랐다(지난 연재 3단계).
  • 미세조정까지 같은 도구로 한다. 지난 연재 10단계에서 mlx-lm으로 작은 모델을 Mac mini에서 25분 동안 LoRA로 가르쳤다.
  • 모델을 바꿔 끼우기 쉽다. 서버 하나에 요청마다 모델 폴더 이름을 적으면, 서버가 그 모델로 바꿔 올린다.
  • Apple Silicon Mac에서만 돈다.
  • 긴 대화에서 메모리가 모자라 멈췄다. 대화 기억을 쓰는 만큼 늘려 가고, 새 요청을 시작할 때 그 기억을 새 자리로 옮기는 동안 잠깐 두 벌이 된다. 코딩 에이전트 시험에서 6번 멈췄다(로컬 모델에게 코딩 맡기기 3편).
  • 멈춰도 알아채기 어렵다. 프로세스가 살아 있어서 서비스 관리자가 다시 띄우지 않는다. 답 요청에는 404를 돌려준다.

Ollama

Ollama는 모델을 이름으로 내려받고(ollama pull), 요청이 오면 올리고, 한동안 쓰지 않으면 내리는 프로그램입니다. OpenAI 형식 API와 함께 Claude 형식 API도 내줘서, Claude Code를 바로 붙일 수도 있습니다. Mac mini에 Homebrew로 0.40.16을 깔아 써 봤습니다.

ollama ps의 출력은 크기, 기억할 글 길이 같은 열을 줄여 옮겼습니다.

  • 가장 쉽다. 설치, 모델 받기, 서버 띄우기가 명령 하나씩이다. 모델 목록과 크기, 지금 올라간 모델도 바로 보인다.
  • 엔진을 모델마다 고른다. 마지막 열(RUNNER)이 엔진이다. 같은 Mac mini에서 Qwen3.8과 Gemma 4는 Ollama가 NVFP4라는 4비트 형식으로 내려받아 MLX 엔진으로 돌렸고, 시험용 작은 모델 Qwen3 0.6B는 llama.cpp 엔진으로 돌렸다.
  • 기본값을 꼭 확인한다. GPU 메모리가 24GiB보다 작으면 기억할 글 길이가 4,096토큰이다. Ollama 문서도 에이전트와 코딩 도구에는 6만 4천 토큰 이상을 권한다. Qwen처럼 생각(추론)을 하는 모델은 기본으로 생각을 켠다.
  • 다른 프로그램이 쓰는 GPU 메모리를 모른다. MLX 서버가 15GB를 쥐고 있는데도 GPU에 22GB가 비어 있다고 봤다. 같은 Mac에서 다른 엔진과 함께 쓰려면 한쪽을 꺼야 한다.
  • 엔진과 파일 형식이 이름 뒤에 숨는다. qwen3.8:27b라는 이름만 봐서는 NVFP4 형식에 MLX 엔진이라는 것을 알 수 없다. 형식을 고르려면 태그를 골라야 한다.

코딩 에이전트 시험 결과는 2편에

같은 Mac mini에서 Ollama로 코딩 에이전트 시험을 돌렸습니다. Claude Code는 요청마다 생각(추론)을 켜 달라고 보냅니다. mlx-lm은 서버 설정으로 생각을 꺼 두어 이 요청과 상관없이 생각하지 않았지만, Ollama는 요청을 따랐습니다. 그래서 생각 요청을 빼고 다시 돌렸습니다. Mac mini 결과는 2편에 썼습니다. Ollama는 24번 내내 멈추지 않았고, Qwen3.8 27B는 mlx-lm 때 3/6에서 6/6이 됐습니다. 노트북 결과는 3편에 씁니다.

어떻게 고를까

이런 경우 고를 것
Mac 하나에서 빠르게, 대화가 짧다 MLX
여러 기계, 늘 켜 둘 서버, 대화가 길다 GGUF와 llama.cpp
처음 시작, 모델을 이것저것 바꿔 본다 Ollama
  • Mac이라면 MLX부터 재 본다. 같은 모델이면 답 쓰기가 빨랐다. 다만 긴 대화를 오래 이어 갈 서버라면 메모리 여유를 넉넉히 둔다.
  • 메모리가 빠듯하면 llama.cpp가 다루기 쉽다. 쓸 자리를 처음에 정해 두니, 모자라면 대개 일찍 드러난다.
  • Ollama는 기본값만 바꾸면 처음 쓰기에 가장 편하다. 기억할 글 길이와 생각 설정을 먼저 확인한다.

알게 된 것

  • 셋은 고르는 대상이 아니라 층이다. GGUF와 MLX는 형식과 엔진이고, Ollama는 그 엔진들을 감싼 프로그램이다.
  • 같은 모델도 엔진에 따라 속도가 다르다. Mac mini에서 MLX가 llama.cpp보다 답 쓰기가 최대 50% 빨랐다.
  • 메모리를 잡는 방식이 안정성을 가른다. llama.cpp는 처음에 잡고, MLX는 쓰는 만큼 늘린다. 긴 대화에서 차이가 드러났다.
  • 편한 도구일수록 기본값을 확인한다. Ollama는 작은 GPU에서 기억할 글 길이를 4천 토큰으로 두고, 생각을 켜 둔다.
