명령으로 켠 Mac 화면 공유는 로그인만 되고 화면을 보내지 않는다

SSH로 화면 공유 서비스를 띄우자 포트도 열리고 로그인도 됐지만, 로그에는 「Unable to capture screen」만 남았습니다. 시스템 설정의 스위치로 켜야 권한이 따라옵니다.

해결됨
대상
macOS 27 화면 공유(screensharingd)
환경

증상

멀리 있는 Mac을 화면 공유로 쓰려고, Mac 앞에 가지 않고 SSH에서 화면 공유를 켰습니다. 다른 Mac에서 접속하면 비밀번호까지는 통과했지만 화면이 오지 않았습니다. 화면 공유 서비스의 로그에는 이렇게 남았습니다.

시스템 설정에서 화면 공유를 켠 다른 Mac은 같은 줄이 postEventFlag 1 screenCaptureFlag 1이었습니다.

재현 순서

  1. SSH로 접속해 관리자 권한으로 화면 공유 서비스를 켠다.
  1. 5900번 포트가 열린다. 다른 Mac에서 vnc://<주소>로 접속하면 로그인은 된다.
  2. 화면이 오지 않는다. /usr/bin/log show --predicate 'process == "screensharingd"'에 위 줄이 남는다.

원인

확인한 것

  • 로그인(RSA-SRP)은 통과했지만, 화면 공유 서비스가 화면 캡처 권한(screenCaptureFlag)과 입력 권한(postEventFlag)을 0으로 받았다.
  • 같은 Mac에서 시스템 설정으로 켠 뒤에는 두 값이 1이 됐다.

추정한 것

  • macOS는 이 두 권한을 시스템 설정의 스위치(또는 MDM 프로필)로 켤 때만 주는 것으로 보인다. 명령으로는 서비스만 뜬다. Apple 문서에서 확인하지는 못했다.

해결

Mac 앞에서 시스템 설정 → 일반 → 공유의 「원격 관리」를 켜자 두 값이 1이 됐습니다. 원격 관리가 켜지면 화면 공유 대신 원격 관리가 접속을 받습니다.

그런데 이번에는 비밀번호를 맞게 넣어도 접속이 거부됐습니다. 원격 관리가 「다음 사용자만」 허용으로 켜졌는데, 권한을 받은 사용자가 아무도 없었기 때문입니다.

srp_server_mech_step: 0은 비밀번호가 맞았다는 뜻입니다. 계정 이름이 틀리면 이 값이 -20으로 나옵니다. 사용자에게 권한을 주는 것은 SSH에서도 됐습니다.

이 뒤로 접속이 되고 화면도 나왔습니다. 처음 한 번은 Mac 앞에서 켜야 하고, 그다음 설정은 원격으로 할 수 있었습니다.

같이 걸린 것: SSH에서는 다운로드 폴더의 파일로 설치하지 못한다

Chrome 원격 데스크톱 호스트를 SSH로 설치하려고 설치 파일을 ~/Downloads에 두었더니, 파일이 있는데도 경로가 틀렸다고 나왔습니다.

installer: Error - the package path specified was invalid: '/Users/<사용자>/Downloads/…/….pkg'.

같은 파일을 /Users/Shared로 옮기자 바로 설치됐습니다. macOS가 SSH 세션에서 다운로드, 문서, 데스크톱 폴더에 닿지 못하게 막는 것으로 보입니다. 시스템 설정의 원격 로그인에는 원격 사용자에게 전체 디스크 접근을 허용하는 선택이 있지만, 켜 보지는 않았습니다.
