LiteLLM 게이트웨이가 표준 밖 요청 필드를 모델 서버까지 그대로 넘긴다

API 키를 확인하는 게이트웨이를 세웠는데, 키를 가진 사람이 넣은 표준 밖 필드는 모델 서버까지 그대로 갔습니다. 받은 필드를 적기만 하는 가짜 서버로 확인했습니다.

상태
우회
대상
LiteLLM 1.106.6 프록시
환경
macOS 27.0, LiteLLM 1.106.6 (Python 3.12), mlx-lm 0.32.2
올린 날
2026-11-16
읽는 시간
약 3분

증상

로컬 모델 서버(mlx_lm.server) 앞에 LiteLLM을 게이트웨이로 세웠습니다. 키마다 쓸 모델과 한도를 정했으니, 키가 있어도 정해 둔 일만 할 수 있다고 여겼습니다. 그런데 요청 본문에 OpenAI 표준에 없는 필드를 넣으면, LiteLLM이 그 필드를 지우지 않고 모델 서버까지 넘겼습니다.

문제는 모델 서버 쪽입니다. mlx_lm.server는 요청 본문의 draft_model과 adapters를 읽어 요청마다 다른 모델이나 어댑터를 불러오고, chat_template_kwargs로는 서버가 정해 둔 템플릿 설정을 바꿉니다. 게이트웨이를 거쳐도 이 필드가 그대로 가면, 키를 가진 사람 누구나 서버가 모델을 더 불러오게 할 수 있습니다. 메모리가 빠듯한 기계라면 서버가 멈추고 모두가 못 쓰게 됩니다.

재현 순서

  1. 받은 본문의 필드 이름만 적고 ok라고 답하는 가짜 서버를 띄운다.
  1. LiteLLM 설정에 이 서버를 OpenAI 호환 모델로 등록하고 프록시를 띄운다.
  1. 표준 밖 필드를 하나 넣어 묻는다. 예: {"model": "echo", "messages": [...], "top_k": 5}.
  2. 가짜 서버의 출력에 top_k가 그대로 찍힌다.

원인

확인한 것

  • LiteLLM은 openai/처럼 OpenAI 호환 공급자로 보낼 때, OpenAI 표준 매개변수 목록에 없는 필드를 모두 extra_body에 담아 보낸다. 지우는 것은 model과 additional_drop_params에 적은 이름뿐이다(1.106.6의 litellm/utils.py, add_provider_specific_params_to_optional_params).
  • drop_params: true는 서버가 지원하지 않는 표준 매개변수를 지우는 설정이라, 이 필드들에는 듣지 않는다.
  • 시험에서 draft_model, adapters, chat_template_kwargs, top_k 네 개가 가짜 서버에 그대로 도착했다.

추정한 것

  • 다른 OpenAI 호환 서버들도 저마다 표준 밖 필드를 받는다. 그 가운데 무엇이 위험한지는 서버마다 따로 봐야 한다.

해결

모델마다 additional_drop_params에 extra_body를 넣었습니다. 표준 밖 필드를 담는 일 자체를 하지 않게 됩니다.

같은 요청을 다시 보내자 가짜 서버에는 max_tokens, messages, model, temperature만 도착했습니다. 대신 top_k처럼 쓸모 있는 표준 밖 값도 함께 버려집니다. 필요한 것이 있으면 extra_body 대신 위험한 필드 이름만 골라 적는 방법도 있습니다.

LiteLLM의 기본 동작 자체는 그대로라서, 상태는 「우회」로 둡니다.
