llama.cpp RPC는 워커의 GPU 계산이 한 번만 실패해도 서버가 통째로 꺼진다

워커 Mac의 메모리가 넘치던 때 macOS가 GPU 오류를 복구하며 계산 하나를 버렸습니다. RPC 서버는 실패한 계산을 이어 가지 못하고 스스로 꺼졌고, 마스터 쪽 서버도 같이 꺼졌습니다.

우회

llama.cpp RPC (build 12341)
환경
macOS 27.0(마스터), 27.2(워커), 마스터 Apple M4 24GB, 워커 Apple M5 Pro 48GB, llama.cpp build 12341(827466b9e), Metal, 썬더볼트 브리지
올린 날
2026-11-26
읽는 시간
약 3분

증상

두 Mac을 썬더볼트로 잇고, llama.cpp RPC로 Qwen3.5 122B-A10B(UD-Q3_K_XL, 57.0GB)를 나눠 올렸습니다. 마스터에서는 llama-server가, 워커에서는 ggml-rpc-server가 돕니다. 140문제 시험을 31분째 돌리던 때 워커의 rpc-server가 이렇게 끝났습니다.

워커의 프로세스는 종료 코드 134(abort)로 끝났습니다. 연결이 끊기자 마스터의 llama-server도 곧바로 꺼졌습니다.

꺼지기 11분쯤 전부터 조짐이 있었습니다. 초당 17토큰으로 답을 쓰던 서버가 몇 분씩 멈췄다가 초당 2토큰 남짓으로 기기를 되풀이했고, 워커의 화면도 멈춘 듯 느려졌습니다.

드러난 과정

일부러 다시 일으켜 보지는 않았습니다. 그때의 조건은 이랬습니다.

  1. 48GB 워커에 GPU 메모리를 23GB쯤 쓰는 다른 프로그램이 올라와 있었다.
  2. 워커에서 ggml-rpc-server -c를 띄우고, 마스터에서 --device MTL0,RPC0 -ts 7,12로 122B를 나눠 올렸다. 워커 몫은 약 37GB였다.
  3. 긴 시험을 돌렸다. 31분 뒤 위 오류로 두 서버가 모두 꺼졌다.

원인

확인한 것

  • rpc-server는 그래프 계산이 성공을 돌려주지 않으면 GGML_ASSERT로 프로세스를 끝냅니다(ggml-rpc.cpp 2289행). 계산 실패를 마스터에 오류로 알리고 버티는 길이 없습니다.
  • Metal 백엔드는 명령 버퍼가 한 번 실패하면 오류 상태로 남고, 되살리려면 백엔드를 다시 만들라고 기록합니다.
  • 마스터의 llama-server도 응답이 끊기면 검사(ggml-rpc.cpp 696행)에 걸려 종료됩니다. 한쪽의 GPU 오류 하나가 두 서버를 다 끝냅니다.
  • 오류 이름의 InnocentVictim은 다른 작업 때문에 난 GPU 오류를 macOS가 복구하면서 함께 버려진 쪽이라는 뜻입니다.

추정한 것

  • 그때 워커에는 다른 프로그램 몫 23GB와 122B 몫 37GB가 함께 있었습니다. 합치면 60GB로 48GB 기계에 넘칩니다. 이것이 GPU 오류의 계기였을 것으로 보지만, 시스템 기록에서 직접 원인을 찾지는 못했습니다.

해결

llama.cpp 쪽에서 고쳐지지 않는 한 우회만 됩니다.

  • 겹치지 않게 했다. 시험 동안 워커에서 GPU를 쓰는 다른 프로그램을 내려 두었다.
  • 다시 올라오면 바로 끄게 했다. 몇 초마다 그 프로그램이 GPU에 다시 올라왔는지 보고, 올라오면 rpc-server를 먼저 끄는 감시 스크립트를 켰다. 서버가 오류로 죽기 전에 시험을 멈추려는 것이다.
  • 결과: 두 번째에는 남은 메모리를 한 번 읽었을 때 8%까지 내려갔지만, 27분 동안 멈추지 않고 끝났다.

RPC로 GPU를 빌려주는 동안에는 워커를 다른 GPU 일에 쓰지 않는 편이 안전합니다. 이 시험의 자세한 내용은 썬더볼트 활용기 5편에 적었습니다.
