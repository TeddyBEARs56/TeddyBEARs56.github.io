launchd로 띄운 PostgreSQL이 언어 설정이 없어 시작하자마자 꺼진다

SSH로 띄울 때는 잘 돌던 PostgreSQL이, 기계가 켜질 때 저절로 뜨는 서비스로 바꾸자 30초마다 켜졌다 꺼지기를 되풀이했습니다. 다른 점은 언어 설정 변수 하나였습니다.

상태
해결됨
대상
PostgreSQL 18 (Homebrew)을 launchd로 띄울 때
환경
macOS 27.0.1, Apple M4, PostgreSQL 18.6 (Homebrew), gettext 1.0
올린 날
2026-11-17
읽는 시간
약 3분

증상

Mac mini에서 Homebrew로 설치한 PostgreSQL 18에 게이트웨이의 API 키와 사용량, 웹 UI의 문서 검색 자료를 담고 있습니다. 처음에는 SSH로 접속해 시작 스크립트를 손으로 실행했고, 18시간 동안 문제가 없었습니다.

기계가 다시 켜져도 저절로 뜨도록 같은 스크립트를 launchd 서비스(LaunchDaemon)로 등록했습니다. 그러자 PostgreSQL이 뜨자마자 꺼졌습니다.

꺼지면 다시 띄우도록(KeepAlive) 해 두어서 launchd가 30초마다 다시 띄웠지만, 매번 같은 오류로 바로 꺼졌습니다.

재현 순서

  1. 시험용 데이터 폴더를 하나 만든다.
  2. 환경 변수를 모두 비우는 env -i로 띄운다. 쓰고 있는 PostgreSQL과 겹치지 않게 포트는 5499로 한다. 띄우지 못하고, 기록 파일에 증상과 같은 오류가 남는다.
  3. LC_ALL=C 하나만 넣고 띄운다. 잘 뜬다.

환경 변수를 모두 비웠는데, 첫 번째 안내 문구는 오히려 한국어로 나왔습니다. 이 Mac의 언어 설정이 한국어입니다.

원인

확인한 것

  • launchd가 띄운 프로세스에는 LANG이나 LC_로 시작하는 언어 설정 변수가 하나도 없다. SSH로 접속한 셸에는 LANG=ko_KR.UTF-8이 있다. 손으로 띄울 때 괜찮았던 이유다.
  • 시험용 폴더로 하나씩 넣어 보니 LANG=ko_KR.UTF-8, LC_ALL=C, LC_ALL=en_US.UTF-8 가운데 하나만 있어도 뜬다. 모두 없을 때만 꺼진다.
  • Homebrew의 PostgreSQL 18은 번역 라이브러리인 gettext의 libintl을 쓴다(otool -L로 확인).
  • PostgreSQL 코드(postmaster.c)에 이 검사의 이유가 적혀 있다. macOS에서 libintl은 언어를 정하는 함수 setlocale을 자기 것으로 바꿔 끼운다. 언어 설정 변수가 모두 비어 있으면 이 함수가 macOS에 언어 설정을 직접 묻는데(CFLocaleCopyCurrent), 이때 프로세스에 스레드가 생긴다. PostgreSQL의 주 프로세스(postmaster)는 자식 프로세스를 만드는 방식(fork)이 스레드가 여럿인 프로그램에서는 안전하지 않아서, 시작하다 스레드를 알아채면 스스로 멈춘다.

추정한 것

  • 재현에서 안내 문구가 한국어로 나온 것도 같은 동작으로 보인다. 변수가 없어서 macOS의 언어 설정을 읽었을 것이다.
  • Homebrew의 brew services로 띄웠다면 겪지 않았을 것이다. Homebrew가 함께 설치한 서비스 파일에는 LC_ALL=en_US.UTF-8이 들어 있다. 직접 만든 서비스 파일에는 이 값이 없었다.

해결

시작 스크립트에서 PostgreSQL을 실행하기 바로 앞에 한 줄을 넣었습니다.

launchd가 30초 뒤 다시 띄우자 바로 접속을 받았고, 게이트웨이 호출과 문서 검색도 정상이었습니다. 서비스 파일(plist)의 EnvironmentVariables에 넣어도 됩니다. Homebrew의 서비스 파일이 그렇게 합니다.

값은 C로 골랐습니다. 이 서버의 데이터베이스가 모두 C로 만들어져 있어서입니다. 정렬 규칙 같은 데이터베이스의 언어 설정은 만들 때 정해지고, 연결마다 그 값을 씁니다(PostgreSQL 코드 main.c의 설명). 그래서 이 한 줄로 저장된 데이터가 달라지지는 않습니다.

서비스로 등록하기 전에 env -i로 시작 스크립트를 한 번 돌려 봤다면 미리 알 수 있었습니다. PostgreSQL은 일부러 시작을 멈췄고 고칠 곳은 시작 스크립트였으므로, 상태는 「해결됨」으로 둡니다.
