llama.cpp RPC 서버의 캐시는 지워지지 않아 이틀 만에 100GB 가까이 쌓였다

모델을 다시 올릴 때 가중치를 네트워크로 받지 않게 해 주는 캐시인데, 크기 한도도 정리도 없습니다. 이틀 동안 99.8GB가 쌓였고, README에 적힌 곳과 다른 폴더에 있었습니다.

증상

두 Mac을 llama.cpp RPC로 묶어, GPU를 빌려주는 워커에서 ggml-rpc-server를 -c(로컬 캐시 켜기)로 띄웠습니다. 이틀 동안 모델 판과 나눔 비율을 여러 번 바꿔 시험한 뒤 워커의 디스크를 보니 캐시 폴더가 이만큼 커져 있었습니다.

du의 「G」는 2진 단위(GiB)라, 10진으로는 99.8GB입니다. 파일은 1,012개였고, 하나가 11MB에서 2.0GB였습니다. 첫날 42.6GB, 둘째 날 57.2GB가 쌓였습니다.

재현 순서

  1. 워커에서 ggml-rpc-server -H <썬더볼트 주소> -p 50052 -c로 띄운다.
  2. 마스터에서 llama-server --rpc <워커 주소>:50052로 모델을 나눠 올린다.
  3. 다른 양자화 판으로 바꾸거나 -ts(나눔 비율)를 바꿔 다시 올린다.
  4. 캐시 폴더가 그만큼 커지고, 줄어들지 않는다.

원인

이 빌드의 코드로 확인했습니다.

  • 무엇을 저장하나: -c를 켜면 마스터가 10MiB보다 큰 가중치 텐서를 보낼 때, rpc-server가 내용의 해시를 이름으로 파일을 저장한다. 다음에 같은 텐서를 보낼 때는 해시만 받고 파일에서 읽는다. 모델을 다시 올릴 때 가중치를 네트워크로 받지 않으려는 기능이다.
  • 지우는 곳이 없다: ggml-rpc.cpp와 rpc-server.cpp에는 캐시 파일을 지우는 코드가 없다. --help에 나오는 캐시 옵션도 -c 하나뿐이라 크기 한도를 정할 수 없다.
  • 판이나 비율이 바뀌면 새로 쌓인다: 이름이 텐서 내용의 해시라서, 양자화 판이 다르면 모두 새 파일이 된다. 나눔 비율을 바꿔 워커가 새로 맡게 된 층도 새 파일로 쌓인다.
  • README와 다른 곳에 있다: README에는 기본 위치가 $HOME/.cache/llama.cpp/rpc라고 적혀 있다. 하지만 macOS에서는 코드가 ~/Library/Caches/llama.cpp/rpc를 쓴다. 환경 변수 LLAMA_CACHE를 주면 그 아래 rpc 폴더로 바뀐다.

해결

지금은 손으로 지우는 수밖에 없습니다.

  • 다 쓴 뒤 지운다. rpc-server를 끈 뒤 ~/Library/Caches/llama.cpp/rpc를 지운다. 다음에 모델을 올릴 때 가중치를 다시 네트워크로 받을 뿐이다.
  • 시험마다 폴더를 나눈다(해 보지는 않았다). LLAMA_CACHE를 시험마다 다른 폴더로 주면, 다 쓴 판의 캐시만 골라 지우기 쉽다.
  • 캐시를 켜지 않는다. -c 없이 띄우면 디스크에 남는 것이 없다. 대신 모델을 올릴 때마다 가중치 전체를 받는다. 캐시로 올리는 시간이 얼마나 줄었는지는 따로 재지 않았다.
