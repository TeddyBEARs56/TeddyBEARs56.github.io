4000번 포트가 쓰이고 있으면 LiteLLM 프록시가 아무 포트에서나 조용히 뜬다

--port 4000으로 띄웠는데 32274번에서 떴습니다. 경고 한 줄 없이 포트만 바뀌었습니다.

상태
우회
대상
LiteLLM 1.106.6 프록시 (litellm 명령)
환경
macOS 27.0, LiteLLM 1.106.6 (Python 3.12), launchd
올린 날
2026-11-16
읽는 시간
약 2분

증상

LiteLLM 프록시를 4000번 포트에 늘 켜 두는 서비스로 만들고 있었습니다. 같은 프록시를 하나 더 띄우면 「포트가 이미 쓰이고 있다」며 멈출 줄 알았습니다. 그런데 오류 없이 다른 포트에서 떴습니다.

서비스 관리자는 프로세스가 살아 있으니 정상으로 봅니다. 4000번을 부르는 프로그램들은 새 프록시를 찾지 못하고, 네트워크에는 계획에 없던 포트가 열립니다. 받는 주소를 0.0.0.0으로 두었다면 같은 네트워크 전체에 열립니다.

재현 순서

  1. 4000번 포트에서 무엇이든 듣고 있게 한다. 예: 이미 떠 있는 LiteLLM.
  2. 프록시를 하나 더 띄운다. 시험용 마스터 키는 즉석에서 만든다.
  1. 출력의 Uvicorn running on 줄에 4000이 아닌 포트가 나온다.

원인

확인한 것

  • 1.106.6의 litellm/proxy/proxy_cli.py에 아래 두 줄이 있다. 포트가 4000이고 이미 쓰이고 있으면, 무작위 번호로 바꾼다.
  • 실제로 띄워 보니 32274번에서 떴다.

추정한 것

  • 조건이 port == 4000이라, 다른 번호를 주면 이렇게 바뀌지 않고 보통처럼 실패할 것이다. 시험하지는 않았다.

해결

시작 스크립트에서 4000번이 비었는지 먼저 확인하고, 쓰이고 있으면 띄우지 않게 했습니다. launchd는 30초 뒤에 다시 시도합니다.

게이트웨이가 도는 중에 이 스크립트를 한 번 더 실행해 보니, 위 문구를 남기고 끝났습니다. 4000이 아닌 번호로 띄우는 것도 방법이지만, 많이 쓰는 기본 번호를 그대로 두려고 이렇게 했습니다.

마스터 키가 없으면 아예 뜨지 않는다

처음 재현할 때는 마스터 키 없이 띄웠다가 「no master key is set, so every request would be accepted without authentication」라며 거절당했습니다. 1.106.6은 인증 없는 프록시를 기본으로 띄우지 않습니다. 그래서 위 명령에 시험용 키를 넣었습니다.
