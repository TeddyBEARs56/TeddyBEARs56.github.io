Mac의 GPU에 올린 모델 메모리는 ps의 RSS에 거의 잡히지 않는다

ps로 3.6GB라던 서버가 실제로는 26GB 가까이 쓰고 있었습니다. 글에 잘못된 값을 쓸 뻔했고, 단위까지 두 군데에서 헷갈렸습니다.

상태
해결됨
대상
macOS의 메모리 표시(ps, footprint, 활동 모니터)
환경
macOS 27.2, Apple M5 Pro 48GB, llama.cpp build 12341의 ggml-rpc-server
올린 날
2026-11-26
읽는 시간
약 2분

증상

두 Mac을 llama.cpp RPC로 묶어 122B 모델을 나눠 올렸습니다. GPU를 빌려주는 워커에서 ggml-rpc-server가 메모리를 얼마나 쓰는지 ps -o rss로 보니 3.6GB였습니다. 셈으로는 모델 몫이 25.6GB였고, 실제로 워커의 스왑도 22GB 남짓까지 늘었습니다. 3.6GB는 맞을 수가 없는 값이었습니다.

드러난 과정

  1. 같은 때 macOS의 footprint로도 봤다. 여기에는 이렇게 나왔다.
  1. 글 초안에는 3.6GB를 활동 모니터의 「메모리」 칸에서 본 값이라고 잘못 적었다. 3.6GB는 ps의 RSS였고, 「메모리」 칸은 오히려 24GB 쪽을 보여 준다.
  2. 초안은 「24 GB」를 10진 GB로 읽어, 다른 때 바이트로 읽은 25.4GB와 서로 다른 양인 것처럼 적었다.
  3. 스왑도 vm.swapusage의 값을 1000으로 나눠 적었다. 세 가지 모두 글을 올리기 전 사실 확인에서 바로잡았다.

원인

확인한 것

  • 활동 모니터의 두 칸이 다르다. 「메모리」 칸은 phys_footprint이고, 「실제 메모리」 칸은 RSS다. 한국어 활동 모니터의 문자열 파일에서 확인했다. top의 MEM 칸도 phys_footprint와 같은 값을 보여 준다.
  • footprint의 단위는 2진이다. 「GB」라고 찍지만 GiB이고, 「MB」도 MiB다. 26,300,009,600B가 「24 GB」(24.5GiB)로 나온다.
  • sysctl vm.swapusage의 「M」도 MiB다. 21,193M은 22.2GB다. 1000으로 나눠 21GB라고 쓰면 어느 단위와도 맞지 않는다.

추정한 것

  • 모델 몫이 RSS에 거의 잡히지 않는 까닭은 GPU용으로 잡은 메모리라서로 보인다. 다만 출력으로 직접 확인하지는 못했다. footprint에서 GPU 메모리를 따로 보여 주는 IOAccelerator 줄은 2MB도 안 됐다.

해결

재는 방법과 단위를 바꿨습니다.

  • phys_footprint로 잰다. footprint -p <pid>, top의 MEM 칸, 활동 모니터의 「메모리」 칸 가운데 하나를 본다. ps의 RSS와 활동 모니터의 「실제 메모리」 칸은 쓰지 않는다.
  • 단위를 맞춘다. GiB를 10진 GB로 바꿀 때는 1.074를 곱한다. 바이트 값이 있으면 바이트로 읽어 직접 나눈다.

바로잡은 값은 썬더볼트 활용기 4편에 적었습니다.

남긴 기록
