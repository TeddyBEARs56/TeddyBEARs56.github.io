Open WebUI를 slim으로 띄우면 문서 검색의 임베딩 모델과 벡터 저장소가 함께 꺼진다

웹 UI가 GPU를 쓰지 않게 하려고 켠 설정이, 문서 검색에 필요한 두 가지를 조용히 꺼 두고 있었습니다. 지식에 글을 넣자 「PGVECTOR_DB_URL을 설정하라」는 503이 났습니다.

상태
우회
대상
Open WebUI 0.13.3
환경
macOS 27.0, Open WebUI 0.13.3 (Python 3.12, uv로 설치), PostgreSQL 18, pgvector 0.8.7, llama.cpp
올린 날
2026-11-17
읽는 시간
약 3분

증상

Mac mini에서 Open WebUI를 Docker 없이 uv로 설치해 씁니다. 같은 기계의 MLX 서버와 GPU 메모리를 다투지 않게 USE_SLIM_DOCKER=true로 띄웠습니다. 이 설정이면 웹 UI가 GPU를 쓰지 않습니다.

나중에 문서 검색을 붙이려고 지식을 만들고 첫 파일을 올렸습니다. 파일은 「실패」 상태가 됐고, 지식에 더하는 API는 400을 돌려줬습니다.

설정에는 임베딩 모델이 기본값 sentence-transformers/all-MiniLM-L6-v2로 그대로 남아 있었습니다. 하지만 이 설정에서는 그 모델을 불러오지 않습니다.

재현 순서

  1. USE_SLIM_DOCKER=true로 Open WebUI 0.13.3을 띄운다. 벡터 저장소와 임베딩 설정은 기본값 그대로 둔다.
  2. 워크스페이스에서 지식을 하나 만들고 Markdown 파일을 올린다.
  3. 파일이 실패 상태가 되고, 오류에 503: Configure PGVECTOR_DB_URL for remote vector storage.가 남는다.

원인

확인한 것 (Open WebUI 0.13.3 코드)

  • env.py: 이 설정이면 GPU(Mac에서는 MPS)를 고르는 부분을 건너뛰고 CPU로 둔다. 여기까지가 원래 바란 효과다.
  • routers/retrieval.py: 웹 UI 안의 임베딩 모델은 engine == '' and not USE_SLIM일 때만 불러온다. 임베딩 엔진을 비워 둔 채(웹 UI 안의 모델) 바꾸려 하면 Slim requires an external embedding engine (openai, ollama, azure_openai).로 거절한다.
  • config.py: 벡터 저장소 기본값이 slim이면 pgvector, 아니면 chroma다. retrieval/vector/factory.py는 slim에서 pgvector가 아닌 저장소를 고르면 Slim requires PostgreSQL/pgvector for vector storage.로 거절한다. 저장소 연결은 처음 쓸 때 만들기 때문에, 서버는 잘 뜨고 첫 파일에서야 오류가 난다.
  • uv tool install open-webui로만 설치하면 pgvector에 붙는 파이썬 부품(pgvector, psycopg2-binary)이 없다. Open WebUI는 이 둘을 postgres 묶음(extra)으로 따로 적어 둔다.

추정한 것

  • 이름처럼 Docker의 slim 이미지를 위한 설정이다. Docker 없이 GPU만 피하려고 켜면, 이 두 가지가 함께 꺼진다는 것을 알기 어렵다.

해결

설정은 그대로 두고, 꺼진 두 가지를 바깥에 세웠습니다.

  • 임베딩: OpenAI 형식의 임베딩 API를 띄우고 웹 UI가 그것을 부르게 했다. 이번에는 llama.cpp로 bge-m3를 CPU에서만 돌렸다.
  • 벡터 저장소: PostgreSQL에 pgvector 확장과 웹 UI 전용 데이터베이스를 만들었다. 확장은 관리자 계정으로 미리 만들었다.
  • 파이썬 부품: Open WebUI가 postgres 묶음에 적어 둔 버전 그대로 웹 UI 설치 폴더에 더했다.

RAG_* 값은 처음 띄울 때만 읽고, 그 뒤로는 관리자 설정의 문서 화면에서 바꿉니다. 다시 띄운 뒤 Markdown 파일 10개가 조각 170개로 들어갔고, 검색도 정상이었습니다. 다만 uv tool install로 Open WebUI를 다시 설치하면 더한 부품 두 개는 다시 넣어야 합니다. Open WebUI의 동작이 바뀐 것은 아니라서 상태는 「우회」로 둡니다.
