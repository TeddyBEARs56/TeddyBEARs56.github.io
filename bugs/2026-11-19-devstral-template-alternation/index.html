Devstral Small 2의 대화 형식이 연달아 온 사용자 메시지를 거절한다

Devstral의 대화 형식은 사용자와 모델이 번갈아 말하는지 검사합니다. Claude Code가 붙인 시스템 메시지가 게이트웨이를 지나며 사용자 메시지가 되자, 첫 요청부터 거절당했습니다.

상태
우회
대상
Devstral Small 2 24B Instruct 2512의 대화 형식
환경
Claude Code 2.1.326, LiteLLM 1.106.6, llama.cpp 빌드 12340(Windows, Vulkan), mlx-lm 0.32.2(macOS 27.0.1)

2026-11-19

증상

Claude Code를 로컬 모델로 돌리는 시험에서 Devstral Small 2만 첫 요청부터 오류로 끝났습니다. 노트북의 llama.cpp 서버는 이렇게 거절했습니다.

Mac mini의 MLX 서버로 돌릴 때는 Claude Code가 「There’s an issue with the selected model」이라고만 띄웠습니다. 과제 셋이 모두 같았습니다.

재현 순서

  1. Claude Code가 LiteLLM 게이트웨이로 요청을 보내게 하고, 게이트웨이 뒤에 Devstral Small 2를 띄운다. 대화 형식은 모델 파일에 든 그대로 둔다.
  2. Claude Code에 아무 일이나 맡긴다.
  3. 첫 요청이 위 오류로 끝난다.

원인

확인한 것

  • Claude Code는 첫 요청부터 사용자 메시지 뒤에 시스템 메시지를 하나 더 붙인다. 작업 환경이나 샌드박스 안내 같은 것이다.
  • 게이트웨이는 대화 중간의 시스템 메시지를 사용자 메시지로 바꿔 넘긴다. 그러면 사용자 메시지가 두 번 연달아 간다.
  • Devstral의 대화 형식(chat template)은 사용자와 모델이 번갈아 말하는지 검사하고, 연달아 오면 오류를 낸다. 같은 시험의 다른 모델들은 원래 대화 형식으로 그대로 돌았다.

해결

대화 형식 파일을 복사해 위의 raise_exception 줄만 주석으로 바꿨습니다. 메시지를 모델의 입력으로 펼치는 부분은 그대로 두었습니다.

엔진 고친 사본을 준 방법
llama.cpp --chat-template-file devstral-agent.jinja
mlx-lm 모델 폴더를 하나 더 만들어 대화 형식 파일만 사본으로 바꾸고, 나머지는 원래 파일을 가리키는 링크로 채웠다

그 뒤로 Devstral은 결과물을 Mac mini에서 6번, 노트북에서 7번 맞게 만들었습니다. 검사를 뺐으니 모델은 학습 때 드물었을 순서를 받습니다. 그 때문에 생긴 문제는 보지 못했습니다.

Ollama 0.40.16에서는 고치지 않고 돌았습니다. Ollama 라이브러리의 Devstral은 이 검사가 없는 Go 템플릿을 씁니다(Ollama로 다시 돌려 보기 3편). 처음 겪은 과정은 로컬 모델에게 코딩 맡기기 2편에 자세히 적었습니다.
