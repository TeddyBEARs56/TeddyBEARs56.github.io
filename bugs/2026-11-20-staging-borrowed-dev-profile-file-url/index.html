스테이징 서버가 개발 설정 프로필을 빌려 써서, 올린 이미지 주소가 개발 서버를 가리킨다

이미지 파일은 스테이징 서버의 디스크에 저장됐는데, 데이터베이스와 화면에는 개발 서버의 주소가 적혔습니다. 다른 환경의 설정 프로필을 빌려 쓰면, 그 프로필에 적힌 「자기 주소」까지 따라옵니다.

상태
우회
대상
스테이징 서버의 배포 설정
환경
컨테이너로 배포하는 API 서버, 환경별 설정 프로필, 공개 파일은 서버 디스크에 저장 (도구 버전은 확인 못 함)
올린 날
2026-11-20
읽는 시간
약 2분

증상

스테이징 서버의 관리 화면에서 로고와 공지 본문 이미지를 올렸습니다. 저장은 성공했습니다. 그런데 화면에는 깨진 그림이 보였습니다.

드러난 과정

  1. 스테이징 API 컨테이너의 작업 정의(컨테이너를 띄우는 설정)에서 환경 변수를 봤다. 「활성 프로필 = dev」 한 줄만 있고, 공개 파일에 관한 설정은 없었다.
  2. 같은 파일 요청을 두 서버의 기록에서 찾았다. 개발 서버에서는 404였고, 스테이징 서버에서는 성공이었다.
  3. 배포로 컨테이너를 바꾼 뒤에는 스테이징 서버에서도 404였다.

원인

  • 스테이징 전용 설정 프로필이 없었다. 그래서 스테이징 API 컨테이너는 환경 변수로 개발 프로필을 켜고 돌았다.
  • 공개 파일 설정은 모두 기본값이었다. 저장 방식의 기본값은 서버 디스크였다. 공개 주소의 기본값은 개발 프로필 설정 파일에 적힌 개발 서버의 API 주소였다.
  • 그래서 파일과 주소가 서로 다른 서버를 가리켰다. 파일은 스테이징 서버 디스크에 저장되고, 데이터베이스와 화면에는 개발 서버 주소가 저장됐다. 브라우저는 개발 서버에서 파일을 찾다가 404를 받았다.
  • 서버 디스크라서 배포 때마다 파일이 사라진다. 컨테이너를 바꾸면 그 디스크도 새것이 된다. 배포 뒤 스테이징 서버에서도 404가 난 까닭이다.

해결

스테이징 작업 정의에 「공개 파일 기본 주소 = 스테이징 API 주소」 환경 변수 한 줄을 넣었습니다. 그 작업 정의를 새 버전으로 등록해 다시 배포했습니다. 컨테이너 이미지는 그대로라 코드는 바꾸지 않았습니다.

  • 새로 올리는 파일은 맞는 주소로 저장된다.
  • 이미 잘못된 주소로 저장된 파일은 다시 올려야 한다.
  • 배포 때마다 파일이 지워지는 문제는 남았다. 근본 해결은 스테이징도 운영 서버처럼 오브젝트 스토리지의 공개 버킷에 올리는 것이다. 공개 버킷을 쓰는 운영 서버에는 이 문제가 없다.

배운 것

환경을 하나 늘릴 때 다른 환경의 프로필을 빌려 쓰면, 그 프로필에 적힌 「자기 주소」 값까지 따라옵니다. 환경마다 달라야 하는 주소는 프로필 기본값에 두지 말고 환경 변수로 반드시 받게 하는 편이 안전합니다. 값이 없으면 서버가 뜨지 않게 해 두면, 빠뜨린 것을 배포할 때 바로 알 수 있습니다.
