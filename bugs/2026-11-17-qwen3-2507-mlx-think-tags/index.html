MLX용 Qwen3 4B Instruct 2507로 LoRA 학습을 하면 답마다 빈 생각 태그가 붙는다

작은 모델을 미세조정했더니 답마다 <think></think>가 글자 그대로 붙어 나왔습니다. 학습 데이터를 대화 형식으로 바꾸는 순간 생긴 태그였고, Qwen 공식판의 대화 형식에는 없는 것이었습니다.

상태
우회
대상
mlx-community/Qwen3-4B-Instruct-2507-4bit의 대화 형식
환경
macOS 27.0, mlx-lm 0.32.0·0.32.2, mlx 0.32.4
올린 날
2026-11-17
읽는 시간
약 3분

증상

질문과 답 208쌍으로 Qwen3 4B Instruct 2507(4비트 MLX판)을 LoRA로 학습했습니다. mlx_lm.lora에 대화 형식({"messages": [...]}) 데이터를 주고, 질문 부분은 손실에서 빼는 --mask-prompt를 켰습니다. 학습한 모델에게 물으니 답마다 앞에 빈 생각 태그가 글자 그대로 붙었습니다.

이 모델은 생각 모드가 없는 Instruct 판이라, 학습 전에는 이런 태그를 쓰지 않았습니다.

재현 순서

  1. mlx-community/Qwen3-4B-Instruct-2507-4bit를 받는다.
  2. 같은 질문을 두 가지로 바꿔 본다. 하나는 답까지 넣은 학습 데이터의 모양이고, 하나는 답을 받기 전의 질문 프롬프트다.
  3. 학습 데이터 쪽에만 빈 생각 태그가 들어 있다.
  1. 이 모델로 mlx_lm.lora --train --mask-prompt를 수백 번 돌리고 물으면, 답 앞에 빈 생각 태그가 붙는다.

원인

확인한 것

  • mlx-lm은 대화 형식 데이터를 학습할 때 대화 전체를 모델의 대화 형식으로 바꾼다. --mask-prompt는 답을 받기 전의 질문 프롬프트 길이까지만 손실에서 뺀다. 그래서 빈 생각 태그는 「배워야 할 답」에 들어간다.
  • 질문 프롬프트에는 태그가 없다. 이 대화 형식은 생각 모드를 끄는 enable_thinking 값도 읽지 않는다. 그러니 답할 때 모델이 태그를 스스로 써 넣는다.
  • Qwen이 올린 공식판(Qwen/Qwen3-4B-Instruct-2507)의 대화 형식에는 <think>가 한 번도 나오지 않는다. 답은 <|im_start|>assistant\n답<|im_end|>로만 바뀐다.
  • mlx-community 판의 chat_template.jinja에는 공식판에 없는 부분이 더 있다. 마지막 답 앞에 <think>\n + 생각 내용 + \n</think>\n\n을 넣는 부분인데, 생각 내용이 비어 있어도 넣는다. 생각 모드가 있는 Qwen3 모델의 대화 형식과 같은 부분이다.

추정한 것

  • 변환할 때 생각 모드가 있는 Qwen3의 대화 형식이 함께 들어간 것으로 보인다. 같은 파일로 대화 전체를 바꿔 학습하는 다른 도구에서도 같은 일이 생길 것이다.

해결

학습할 때만 쓰는 모델 폴더 사본을 만들었습니다. 가중치 파일은 링크로 두고, 대화 형식에서 빈 태그를 넣는 조건 한 줄만 바꿨습니다. 생각 내용이 있을 때만 태그를 넣게 한 것입니다.

사본에서는 학습 데이터가 <|im_start|>assistant\n답<|im_end|>로 바뀌고, 질문 프롬프트가 그 앞부분과 정확히 같아집니다. 같은 데이터로 다시 학습하자 태그가 사라졌습니다. 답을 받을 때는 원래 폴더를 그대로 씁니다. 질문 프롬프트는 두 폴더에서 같기 때문입니다. 공식판의 대화 형식을 그대로 가져다 써도 됩니다.

올라간 파일은 그대로라서 상태는 「우회」로 둡니다.
